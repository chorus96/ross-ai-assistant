# RTL Linting Skill
# RTL 린팅 스킬

## Purpose
## 목적

Runs Vivado's RTL linter (`synth_design -lint`) to catch design issues — syntax errors,
Vivado의 RTL linter(`synth_design -lint`)를 실행하여 설계 문제(구문 오류,
undriven signals, arithmetic overflow, inferred latches — before full synthesis.
구동되지 않은 신호, 산술 오버플로, 유추된 래치 — 전체 합성 이전.

**Expected outcome:** A markdown report with every linter violation, diff-formatted code
**예상 결과:** 모든 Linter 위반, diff 형식 코드가 포함된 마크다운 보고서
fixes, resolution-guide-backed recommendations, and UG901 references.
수정 사항, 해결 가이드 지원 권장 사항 및 UG901 참조.

**Prerequisites:**
**전제조건:**
- RTL source files exist and are syntactically valid (parseable by Vivado)
- RTL 소스 파일이 존재하고 구문적으로 유효합니다(Vivado에서 구문 분석 가능).
- Vivado project (.xpr) OR source files in workspace for non-project mode
- 비프로젝트 모드를 위한 작업 공간의 Vivado 프로젝트(.xpr) 또는 소스 파일
- Write access to project directory for report generation
- 보고서 생성을 위한 프로젝트 디렉터리에 대한 쓰기 액세스 권한

## When to Use
## 사용 시기

- User asks to lint RTL, check HDL code, run linter, or find RTL issues
- 사용자가 RTL 린트, HDL 코드 확인, 린터 실행 또는 RTL 문제 찾기를 요청합니다.
- After writing new modules or modifying existing RTL (early development cycle)
- 새 모듈을 작성하거나 기존 RTL을 수정한 후(초기 개발 주기)
- Iterative fix-and-verify workflow (apply fixes, re-run linter)
- 반복적인 수정 및 확인 워크플로(수정 사항 적용, Linter 다시 실행)

## When NOT to Use
## 사용하지 말아야 할 때

- RTL has syntax errors preventing elaboration → fix syntax first
- RTL에는 정교화를 방해하는 구문 오류가 있습니다. → 구문을 먼저 수정하세요.
- Need full synthesis analysis → run `synth_design` without `-lint`
- 전체 합성 분석 필요 → `-lint` 없이 `synth_design` 실행
- Post-synthesis/implementation issues → use timing/DRC reports
- 합성 후/구현 문제 → 타이밍/DRC 보고서 사용
