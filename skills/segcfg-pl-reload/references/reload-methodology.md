# PL Reload Methodology for Segmented Configuration
# 분할된 구성을 위한 PL 재로드 방법론

## Concept
## 개념

PL Reload allows users to dynamically change the PL domain configuration without rebooting the PS domain.
PL Reload를 사용하면 사용자는 PS 도메인을 재부팅하지 않고도 PL 도메인 구성을 동적으로 변경할 수 있습니다.
This provides a simplified DFX-like capability without requiring the full DFX design flow in Vivado.
이는 Vivado에서 전체 DFX 설계 흐름을 요구하지 않고도 단순화된 DFX와 유사한 기능을 제공합니다.

- **boot.pdi** is fixed — defines PS domain, DDR, hard blocks
- **boot.pdi**는 고정됨 — PS 도메인, DDR, 하드 블록을 정의합니다.
- **pld.pdi** is swappable — can be replaced with different PL designs at runtime
- **pld.pdi**는 교체 가능 — 런타임 시 다른 PL 설계로 교체 가능
- PLM automatically manages PS-PL boundary isolation during reload
- PLM은 다시 로드하는 동안 PS-PL 경계 격리를 자동으로 관리합니다.

## Requirements
## 요구사항

1. All PLD variants must be compiled against the **same Vivado release** as the boot image
1. 모든 PLD 변형은 부팅 이미지와 **동일한 Vivado 릴리스**에 대해 컴파일되어야 합니다.
2. `pr_verify` is **mandatory** before deploying any PLD variant to hardware
2. PLD 변형을 하드웨어에 배포하기 전에 `pr_verify`는 **필수**입니다.
3. The golden (initial) design must be a **superset** of all PS-PL connectivity
3. 골든(초기) 디자인은 모든 PS-PL 연결의 **상위 세트**여야 합니다.

## Flow Overview
## 흐름 개요

```
Golden Project (superset design)
├── Implement through route_design
├── .ncr file auto-generated
├── Run pr_verify -segcfg_only (golden vs golden = trivially passes)
└── Produce golden_boot.pdi + golden_pld.pdi

Variant Project (PL changes only)
├── Spawn from golden project
├── Import golden .ncr file
├── Modify PL domain ONLY
├── Implement through route_design
├── Run pr_verify -segcfg_only -initial golden.dcp -additional variant.dcp
└── Produce golden_boot.pdi (identical) + variant_pld.pdi
```

## Golden Project: Definition and Construction
## 골든 프로젝트: 정의 및 구축

The golden project:
황금 프로젝트:
- Establishes the **maximum PS-PL boundary** connectivity
- **최대 PS-PL 경계** 연결 설정
- Defines the **superset** of NoC paths, pin usage, and address apertures
- NoC 경로, 핀 사용 및 주소 구멍의 **상위 집합**을 정의합니다.
- Does NOT have to be the first image deployed to hardware
- 하드웨어에 배포된 첫 번째 이미지일 필요는 없습니다.
- Must contain ALL potential connections from PS/CPM to PL that any variant might need
- 모든 변형에 필요할 수 있는 PS/CPM에서 PL까지의 모든 잠재적 연결을 포함해야 합니다.

### Golden project tips
### 골든 프로젝트 팁
- Include HSDP-to-ILA connection in golden if you plan to debug PL via ILA in any variant
- 모든 변형에서 ILA를 통해 PL을 디버깅하려는 경우 골든에 HSDP-ILA 연결을 포함합니다.
- Include all potential PL NMU connections in golden's NoC
- Golden의 NoC에 모든 잠재적인 PL NMU 연결을 포함합니다.
- Future variants may use fewer connections (subsets are OK)
- 향후 변형에서는 더 적은 수의 연결을 사용할 수 있습니다(하위 집합은 괜찮습니다).
- Future variants cannot add new connections beyond what golden defined
- 미래의 변형은 황금이 정의한 것 이상으로 새로운 연결을 추가할 수 없습니다.

## Spawning a PL Variant
## PL 변형 생성

Choose one method to create a variant project:
변형 프로젝트를 만들려면 다음 방법 중 하나를 선택하세요.

### Method A: Save Project As (Heaviest, Easiest)
### 방법 A: 프로젝트를 다른 이름으로 저장(가장 무거움, 가장 쉬움)
```tcl
save_project_as variant_project_name
# Then modify PL logic only; never touch PS/CIPS/NoC/DDR
```

### Method B: Import Block Design Files (Recommended)
### 방법 B: 블록 설계 파일 가져오기(권장)
```tcl
# In the new project, import the golden BD directory
import_files <golden_project_path>/<golden_project>.gen/sources_1/bd
```
This copies the BD and all generated output products into the new project.
이렇게 하면 BD와 생성된 모든 출력 제품이 새 프로젝트에 복사됩니다.

### Method C: Script the Block Design
### 방법 C: 블록 설계 스크립팅
```tcl
# Export golden BD as Tcl script
write_bd_tcl -force golden_design.tcl

# For PS domain only (safer for separation):
write_bd_tcl -hier_blks ps_hierarchy -force golden_ps.tcl
```
In the variant project, source the script to recreate the BD, then add PL modifications.
변형 프로젝트에서 스크립트를 소싱하여 BD를 다시 만든 다음 PL 수정 사항을 추가합니다.

**WARNING**: Never use `read_bd` — it creates a reference (not a copy) to the original .bd file.
**경고**: `read_bd`를 사용하지 마십시오. 원본 .bd 파일에 대한 참조(사본 아님)가 생성됩니다.
Modifications in the variant project will corrupt the golden source.
변형 프로젝트를 수정하면 골든 소스가 손상됩니다.

## NoC Solution File (.ncr)
## NoC 솔루션 파일(.ncr)

The `.ncr` file stores the NoC routing solution in JSON format.
`.ncr` 파일은 NoC 라우팅 솔루션을 JSON 형식으로 저장합니다.
It is generated by running `write_noc_solution` in the golden project after `route_design` completes:
이는 `route_design`이 완료된 후 골든 프로젝트에서 `write_noc_solution`을 실행하여 생성됩니다.

```tcl
# Run in golden project after route_design — generates <design>.ncr in the impl run directory
write_noc_solution
```

### Import in Variant Project
### 변형 프로젝트에서 가져오기
```tcl
# Method 1: Direct Tcl command (call before place_design)
read_noc_solution -file <golden_project>/impl_1/<design>.ncr

# Method 2: Set on implementation run (recommended for scripted flows)
set_property NOC_SOLUTION_FILE <absolute_path_to_golden>.ncr [get_runs impl_1]

# Method 3: GUI — Implementation Run Properties → NOC_SOLUTION_FILE field
```

The `read_noc_solution` command is called automatically by Vivado during `place_design` when `NOC_SOLUTION_FILE` is set.
`read_noc_solution` 명령은 `NOC_SOLUTION_FILE`이 설정된 경우 `place_design` 중에 Vivado에 의해 자동으로 호출됩니다.

## pr_verify
## pr_verify

```tcl
# Run AFTER route_design in the variant project
# -initial must be the golden routed DCP
pr_verify \
    -initial <golden_project>/impl_1/<golden>_routed.dcp \
    -additional <variant_project>/impl_1/<variant>_routed.dcp
```

See `pr-verify-checks.md` for error codes and resolution guidance.
오류 코드 및 해결 지침은 'pr-verify-checks.md'를 참조하세요.

## Supported Design Changes Between Variants
## 변형 간 지원되는 디자인 변경

| Change<br>변경 | Supported<br>지원됨 | Notes<br>메모 |
|--------|-----------|-------|
| PL logic modifications<br>PL 논리 수정 | Yes<br>예 | Keep PS domain frozen<br>PS 도메인을 고정 상태로 유지 |
| PL NoC IP changes<br>PL NoC IP 변경 | Yes (with caution)<br>예(주의해서) | Use separate NoC IP instance for PL-only paths<br>PL 전용 경로에는 별도의 NoC IP 인스턴스 사용 |
| Reducing PS-PL connections<br>PS-PL 연결 줄이기 | Yes<br>예 | Tie off unused ports<br>사용하지 않는 포트 묶기 |
| Adding NEW PS-PL connections<br>새로운 PS-PL 연결 추가 | No | Not permitted; golden must be the superset<br>허용되지 않습니다. 황금은 슈퍼세트여야 해 |
| Modifying CIPS/PS IP<br>CIPS/PS IP 수정 | No | Changes the boot PDI Unique ID<br>부팅 PDI 고유 ID를 변경합니다. |
| Modifying PS-side NoC IP<br>PS 측 NoC IP 수정 | No | Changes boot path configuration<br>부팅 경로 구성 변경 |
| Modifying DDR settings<br>DDR 설정 수정 | No | Changes boot partition<br>부팅 파티션 변경 |
| Enabling DFX within PL<br>PL 내에서 DFX 활성화 | No | Not yet supported in 2025.2<br>2025.2에서는 아직 지원되지 않습니다. |
