# 8-279: Generate Expression Not Constant
# 8-279: 상수가 아닌 표현식 생성

**Message:** `[Synth 8-279] expression in generate statements should resolve to a constant`
**메시지:** `생성 문의 [Synth 8-279] 표현식은 상수로 해석되어야 합니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-279] expression in generate statements should resolve to a constant [/path/to/file.v:42]
```

---

## Root Cause
## 근본 원인

Generate statements (`generate if`, `generate for`, `generate case`) are evaluated at elaboration time, so all controlling expressions must be compile-time constants.
생성 문(`generate if`, `generate for`, `generate case`)은 정교화 시 평가되므로 모든 제어 표현식은 컴파일 시간 상수여야 합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Signal in Generate If
### P1: 생성 신호

```verilog
// Before - signal in generate condition
input enable;
generate
  if (enable)  // ERROR: enable is a signal, not constant
    assign out = in1;
  else
    assign out = in2;
endgenerate

// After - use parameter
parameter ENABLE = 1;
generate
  if (ENABLE)
    assign out = in1;
  else
    assign out = in2;
endgenerate
```

### P2: Non-constant in Generate For
### P2: 생성 대상이 일정하지 않음

```verilog
// Before - variable bound
input [7:0] count;
generate
  for (genvar i = 0; i < count; i = i + 1)  // ERROR
    assign data[i] = src[i];
endgenerate

// After - constant bound
parameter COUNT = 8;
generate
  for (genvar i = 0; i < COUNT; i = i + 1)
    assign data[i] = src[i];
endgenerate
```

### P3: Signal in Generate Case
### P3: 생성 케이스의 신호

```verilog
// Before - signal selector
input [1:0] mode;
generate
  case (mode)  // ERROR: mode is runtime signal
    2'b00: ...
    2'b01: ...
  endcase
endgenerate

// After - use parameter
parameter MODE = 2'b00;
generate
  case (MODE)
    2'b00: ...
    2'b01: ...
  endcase
endgenerate
```

---

## Runtime Alternative
## 런타임 대안

If runtime selection is needed, use regular conditional logic:
런타임 선택이 필요한 경우 일반 조건부 논리를 사용하십시오.

```verilog
// Runtime selection with mux
always @(*) begin
  case (mode)
    2'b00: out = in1;
    2'b01: out = in2;
    default: out = in3;
  endcase
end

// Or ternary
assign out = enable ? in1 : in2;
```

---

## Fix Strategy
## 전략 수정

1. Make every controlling expression of a `generate if`/`for`/`case` a compile-time constant — use `parameter`, `localparam`, or `genvar`, never a runtime signal/port.
1. `generate if`/`for`/`case`의 모든 제어 표현식을 컴파일 타임 상수로 만드세요. `parameter`, `localparam`, `genvar`을 사용하세요. 절대 런타임 신호/포트가 아닙니다.
2. If the value must be static, promote the offending signal to a parameter and pass it through the module hierarchy.
2. 값이 정적이어야 하는 경우 문제가 되는 신호를 매개변수로 승격하고 모듈 계층을 통해 전달합니다.
3. If the selection is genuinely runtime, move it out of the `generate` block into ordinary logic (`always @(*)` `case`, or a ternary/mux).
3. 선택 항목이 실제로 런타임인 경우 `generate` 블록에서 일반 논리(`always @(*)` `case` 또는 삼항/mux)로 이동합니다.
4. Re-run elaboration to confirm the `8-279` error is cleared.
4. '8-279' 오류가 지워졌는지 확인하기 위해 정교화를 다시 실행하세요.
