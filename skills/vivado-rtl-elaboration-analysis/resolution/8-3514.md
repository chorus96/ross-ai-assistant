# 8-3514: cannot infer block ram on a
# 8-3514: 블록 램을 추론할 수 없습니다.

**Message:** `[Synth 8-3514] cannot infer block ram on a non-memory variable 'bRam'`
**메시지:** `[Synth 8-3514]는 비메모리 변수 'bRam'에서 블록 램을 추론할 수 없습니다`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A `ram_style = "block"` attribute (or similar RAM directive) is applied to an
`ram_style = "block"` 속성(또는 유사한 RAM 지시어)이
object that is not a memory array, so Vivado cannot map it to a Block RAM.
메모리 배열이 아닌 객체이므로 Vivado는 이를 블록 RAM에 매핑할 수 없습니다.
The
는
target signal/variable is a scalar or plain vector, not an array of elements
목표 신호/변수는 요소 배열이 아닌 스칼라 또는 일반 벡터입니다.
indexed by an address, which is what BRAM inference requires.
BRAM 추론에 필요한 주소로 인덱싱됩니다.

## Common Patterns
## 일반적인 패턴

### P1: ram_style attribute on a non-memory signal
### P1: 비메모리 신호의 ram_style 속성

**Problematic Code:**
**문제가 있는 코드:**
```vhdl
-- 'bRam' is a scalar/vector, not an addressable array
signal bRam : std_logic_vector(7 downto 0);
attribute ram_style : string;
attribute ram_style of bRam : signal is "block";   -- WARNING: not a memory
```

**Fix - declare the object as an addressable memory array:**
**수정 - 객체를 주소 지정 가능한 메모리 배열로 선언:**
```vhdl
type ram_t is array (0 to 255) of std_logic_vector(7 downto 0);
signal bRam : ram_t;
attribute ram_style : string;
attribute ram_style of bRam : signal is "block";   -- now inferable as BRAM
```

### P2: Memory too small / read style prevents BRAM
### P2: 메모리가 너무 작음/읽기 스타일로 인해 BRAM이 방해됨

**Fix - use a synchronous read and a depth large enough for BRAM:**
**수정 - 동기식 읽기 및 BRAM에 충분한 깊이 사용:**
```vhdl
process(clk)
begin
  if rising_edge(clk) then
    if we = '1' then
      bRam(to_integer(unsigned(addr))) <= din;
    end if;
    dout <= bRam(to_integer(unsigned(addr)));  -- registered (synchronous) read
  end if;
end process;
```

## Fix Strategy
## 전략 수정

1. Apply `ram_style`/BRAM attributes only to an actual **memory array** (an array type indexed by an address), not to a scalar or plain vector.
1. 'ram_style'/BRAM 속성은 스칼라나 일반 벡터가 아닌 실제 **메모리 배열**(주소로 인덱스된 배열 유형)에만 적용됩니다.
2. Declare the object as `array (0 to DEPTH-1) of <element type>` and access it via an address index so it is recognizable as a memory.
2. 객체를 '<요소 유형>의 배열(0 ~ DEPTH-1)'로 선언하고 주소 인덱스를 통해 접근하여 메모리로 인식할 수 있도록 합니다.
3. Use a **synchronous (registered) read** inside a clocked process - asynchronous reads force distributed RAM/LUTs and block BRAM inference.
3. 클록 프로세스 내에서 **동기(등록된) 읽기**를 사용합니다. 비동기 읽기는 분산 RAM/LUT를 강제하고 BRAM 추론을 차단합니다.
4. Ensure the memory is deep/wide enough to justify BRAM; very small arrays may be intentionally implemented as distributed RAM (use `ram_style = "distributed"` if that is desired).
4. 메모리가 BRAM을 정당화할 만큼 충분히 깊고 넓은지 확인하십시오. 매우 작은 배열은 의도적으로 분산 RAM으로 구현될 수 있습니다(원하는 경우 `ram_style = "distributed"` 사용).
5. If BRAM was not actually intended, remove the `ram_style = "block"` attribute to clear the warning.
5. BRAM이 실제로 의도된 것이 아닌 경우 `ram_style = "block"` 속성을 제거하여 경고를 지웁니다.
