# 8-85: always block has no event control
# 8-85: 항상 블록에는 이벤트 제어가 없습니다.

**Message:** `[Synth 8-85] always block has no event control specified`
**메시지:** `[Synth 8-85] 항상 블록에 지정된 이벤트 제어가 없습니다`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

An `always` block has no event control (`@(...)`) and no delay/timing control.
`always` 블록에는 이벤트 제어(`@(...)`)와 지연/타이밍 제어가 없습니다.
A bare `always begin ... end` is a zero-delay infinite loop — it is not
'항상 시작 ... 끝'은 지연이 없는 무한 루프입니다.
synthesizable and Vivado cannot determine whether combinational or sequential
합성 가능하며 Vivado는 조합인지 순차적인지 결정할 수 없습니다.
logic was intended.
논리는 의도되었다.

---

## Common Patterns
## 일반적인 패턴

### P1: Combinational logic missing sensitivity list
### P1: 조합논리 누락 민감도 목록

**Problematic Code:**
**문제가 있는 코드:**
```systemverilog
reg veGatedNandOut;
always begin                                   // ERROR: no event control
  if (veGatedNandIn1[0] && veGatedNandIn1[1] == 1'b1)
    veGatedNandOut = 1'b1;
  else
    veGatedNandOut = 1'b0;
end
```

**Fix — add `@(*)` (or use `always_comb`):**
**수정 — `@(*)` 추가(또는 `always_comb` 사용):**
```systemverilog
reg veGatedNandOut;
always @(*) begin                              // combinational sensitivity
  if (veGatedNandIn1[0] && veGatedNandIn1[1] == 1'b1)
    veGatedNandOut = 1'b1;
  else
    veGatedNandOut = 1'b0;
end
```

### P2: Sequential logic missing clock edge
### P2: 클록 에지가 없는 순차 논리

**Problematic Code:**
**문제가 있는 코드:**
```systemverilog
always begin                                   // ERROR: no event control
  q <= d;
end
```

**Fix — add a clock edge (or use `always_ff`):**
**수정 — 시계 에지 추가(또는 `always_ff` 사용):**
```systemverilog
always @(posedge clk) begin
  q <= d;
end
```

### P3: One-time initialization block
### P3: 일회성 초기화 블록

**Fix — if a single-pass block was intended, use `initial` instead of `always`:**
**수정 — 단일 패스 차단을 의도한 경우 `always` 대신 `initial`을 사용하세요.**
```systemverilog
initial begin
  mem_ready = 1'b0;
end
```

## Fix Strategy
## 전략 수정

1. Decide the intent of the block, then give it explicit event/timing control:
1. 블록의 의도를 결정한 다음 명시적인 이벤트/타이밍 제어를 제공합니다.
   - **Combinational:** `always @(*)` or `always_comb`.
   - **조합:** `항상 @(*)` 또는 `항상_comb`.
   - **Sequential:** `always @(posedge clk)` (add `or negedge rst_n` for async reset) or `always_ff`.
   - **순차적:** `always @(posedge clk)`(비동기 재설정의 경우 `or negedge rst_n` 추가) 또는 `always_ff`.
   - **One-time init:** replace `always` with `initial`.
   - **일회성 초기화:** '항상'을 '초기'로 바꿉니다.
2. Never leave a bare `always begin ... end` — with no event or delay control it is a zero-delay infinite loop and is unsynthesizable.
2. '항상 시작 ... 끝'을 그대로 두지 마십시오. 이벤트나 지연 제어가 없으면 지연이 없는 무한 루프이며 합성할 수 없습니다.
3. Prefer `always_comb`/`always_ff` in SystemVerilog so the tool checks intent and flags accidental latches or missing edges.
3. SystemVerilog에서 `always_comb`/`always_ff`를 선호하면 도구가 의도를 확인하고 우발적인 래치 또는 누락된 가장자리에 플래그를 지정합니다.
4. Verify the sensitivity list is complete for combinational logic (all read signals) — incomplete lists cause simulation/synthesis mismatches; `@(*)` avoids this.
4. 조합 논리(모든 읽기 신호)에 대한 민감도 목록이 완전한지 확인하십시오. 불완전한 목록은 시뮬레이션/합성 불일치를 유발합니다. `@(*)`는 이를 방지합니다.
