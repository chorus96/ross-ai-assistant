# 8-206: Constant Expression Required
# 8-206: 상수 표현식 필요

**Message:** `[Synth 8-206] constant expression required`
**메시지:** `[Synth 8-206] 상수 표현이 필요합니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-206] constant expression required [/path/to/file.vhd:42]
```

---

## Root Cause
## 근본 원인

A value that must be known at compile/elaboration time uses a runtime signal or non-constant expression.
컴파일/작성 시 알아야 하는 값은 런타임 신호 또는 상수가 아닌 표현식을 사용합니다.
Synthesis requires certain values to be constants.
합성에서는 특정 값이 상수여야 합니다.

### Where Constants Are Required
### 상수가 필요한 경우

| Context<br>맥락 | Requires Constant<br>상수 필요 |
|---------|-------------------|
| Generic/parameter values<br>일반/매개변수 값 | Yes<br>예 |
| Array bounds<br>배열 경계 | Yes<br>예 |
| Generate loop bounds<br>루프 경계 생성 | Yes<br>예 |
| Case statement labels<br>사례 설명 라벨 | Yes<br>예 |
| Part-select indices (Verilog)<br>부분 선택 인덱스(Verilog) | Yes (unless +: or -:)<br>예(+: 또는 -: 제외) |
| Signal widths<br>신호 폭 | Yes<br>예 |

## Common Patterns
## 일반적인 패턴

### P1: Signal Used as Generic Value
### P1: 일반 값으로 사용되는 신호

```vhdl
-- Before - signal A,B used in generic map (must be constant)
entity addern is
  generic(
    function my_func (in1,in2:std_logic) return std_logic;
    width : std_logic := '1'
  );
  port(A, B : in std_logic; Y, Y1 : out std_logic);
end addern;

architecture bhv of addern is
begin
  Y <= my_func(A,B);
  -- ERROR: my_func(A,B) is not constant
  U0: entity work.addern2 generic map(width => my_func(A,B)) port map (A,B,Y1);
end bhv;
```

```diff
-- After - use constant value
  U0: entity work.addern2 generic map(width => '1') port map (A,B,Y1);
```

### P2: Variable Used in Array Bounds
### P2: 배열 경계에 사용되는 변수

```verilog
// Before - variable used in array size
input [7:0] size;
reg [7:0] data [0:size-1];  // ERROR: constant expression required
```

```diff
// After - use parameter
+ parameter SIZE = 8;
- reg [7:0] data [0:size-1];
+ reg [7:0] data [0:SIZE-1];
```

### P4: VHDL Record Aggregate in Generic Map
### P4: 일반 맵의 VHDL 레코드 집계

```vhdl
-- Before - record aggregate in generic map using unsigned'(hex)
-- Package defines:
--   type item_t is record
--     BASE_ADDR : unsigned(31 downto 0);
--     LINE_OFFS : unsigned(31 downto 0);
--   end record;
--   type config_t is array(0 to 15) of item_t;

i_module: entity lib.module
  generic map(
    G_CONFIG => (
      0 => (BASE_ADDR => unsigned'(x"0000_0000"),  -- ERROR: constant expression required
            LINE_OFFS => unsigned'(x"0000_0800")),
      1 => (BASE_ADDR => unsigned'(x"0020_0000"),
            LINE_OFFS => unsigned'(x"0000_0800"))
    )
  );
```

**Root Cause:** `unsigned'(x"0000_0000")` is a type qualification on a hex string
**근본 원인:** `unsigned'(x"0000_0000")`는 16진수 문자열의 유형 한정입니다.
literal.
문자 그대로.
The hex literal `x"0000_0000"` is `std_logic_vector` with width inferred
16진수 리터럴 `x"0000_0000"`은 너비가 추론된 `std_logic_Vector`입니다.
from context, but `unsigned'(...)` qualification does NOT set the width — it only
문맥에서 볼 수 있지만 `unsigned'(...)` 자격은 너비를 설정하지 않습니다.
reinterprets the type.
유형을 재해석합니다.
Vivado cannot resolve the width at elaboration time, so it
Vivado는 정교화 시간에 너비를 해결할 수 없으므로
reports "constant expression required".
"상수 표현이 필요함"을 보고합니다.

**Common co-issue:** `use ieee.numeric_std.all;` may be commented out or missing
**일반적인 공동 문제:** 'ieee.numeric_std.all 사용'이 주석 처리되거나 누락될 수 있습니다.
in the architecture region, which prevents `unsigned` type resolution entirely.
이는 '부호 없는' 유형 확인을 완전히 방지하는 아키텍처 영역입니다.

**Fix Options (in order of preference):**
**수정 옵션(선호도 순):**

1. **Use `to_unsigned()` function** (matches package default constant style):
1. **`to_unsigned()` 함수를 사용하세요** (패키지 기본 상수 스타일과 일치):
```diff
  generic map(
    G_CONFIG => (
-     0 => (BASE_ADDR => unsigned'(x"0000_0000"),
-           LINE_OFFS => unsigned'(x"0000_0800")),
+     0 => (BASE_ADDR => to_unsigned(16#0000_0000#, 32),
+           LINE_OFFS => to_unsigned(16#0000_0800#, 32)),
    )
  );
```

2. **Define a named constant** in the architecture declarative region:
2. **아키텍처 선언 영역에서 명명된 상수를 정의**합니다.
```diff
+ constant C_ADDRMAP : maxi_addrmap_t := (
+   0 => (BASE_ADDR => to_unsigned(0, 32),
+         LINE_OFFS => to_unsigned(16#800#, 32),
+         BUFF_OFFS => to_unsigned(16#0100_0000#, 32)),
+   1 => (BASE_ADDR => to_unsigned(16#0020_0000#, 32),
+         LINE_OFFS => to_unsigned(16#800#, 32),
+         BUFF_OFFS => to_unsigned(16#0100_0000#, 32)),
+   others => C_ADDR_DEFAULT
+ );
  i_module: entity lib.module
-   generic map(G_CONFIG => (0 => (...), ...))
+   generic map(G_CONFIG => C_ADDRMAP)
```

3. **Ensure `ieee.numeric_std.all` is imported** in both entity and architecture:
3. **'ieee.numeric_std.all'을 엔터티와 아키텍처 모두에서 가져왔는지 확인하세요**:
```diff
  library ieee;
  use ieee.std_logic_1164.all;
+ use ieee.numeric_std.all;
```

**Diagnostic checklist (MUST follow before proposing fix):**
**진단 체크리스트(수정을 제안하기 전에 따라야 함):**
1. Read the package that defines the record type — check field types and widths
1. 레코드 유형을 정의하는 패키지 읽기 - 필드 유형 및 너비 확인
2. Check if `ieee.numeric_std.all` is imported where the generic map is written
2. 일반 맵이 작성된 위치에서 `ieee.numeric_std.all`을 가져왔는지 확인하세요.
3. Look at the package's default constant (e.g.
3. 패키지의 기본 상수를 살펴보세요(예:
3. `C_ADDR_DEFAULT`) for correct syntax
3. `C_ADDR_DEFAULT`) 올바른 구문
4. Match the aggregate syntax exactly to the type definition
4. 집계 구문을 유형 정의와 정확하게 일치시키세요.
5. Use `to_unsigned(value, width)` instead of `unsigned'(x"...")` for hex literals
5. 16진수 리터럴의 경우 `unsigned'(x"...")` 대신 `to_unsigned(value, width)`를 사용하세요.
6. Fill ALL array indices or use `others =>` for remaining entries
6. 모든 배열 인덱스를 채우거나 나머지 항목에 `others =>`를 사용하세요.

### P3: Signal Used in Generate
### P3: 생성에 사용되는 신호

```verilog
// Before - signal in generate condition
wire [3:0] sel;
generate
  if (sel == 4'b0001)  // ERROR: constant expression required
    assign out = in1;
endgenerate
```

```diff
// After - use parameter
+ parameter SEL = 4'b0001;
  generate
-   if (sel == 4'b0001)
+   if (SEL == 4'b0001)
      assign out = in1;
  endgenerate
```

## Fix Strategy
## 전략 수정

1. Identify the non-constant expression
1. 상수가 아닌 표현식 식별
2. Determine if it can be replaced with a parameter/generic
2. 매개변수/일반으로 대체할 수 있는지 확인
3. If runtime selection is needed, use multiplexer logic instead of generate
3. 런타임 선택이 필요한 경우 생성 대신 멀티플렉서 로직을 사용하십시오.
