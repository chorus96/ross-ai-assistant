# 8-7186: RAM Style Attribute Ignored
# 8-7186: RAM 스타일 속성이 무시됨

**Message:** `[Synth 8-7186] Applying attribute ram_style is ignored, object is not a RAM`
**메시지:** `[Synth 8-7186] ram_style 속성 적용이 무시되고 개체가 RAM이 아닙니다`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

The `ram_style` attribute is applied to something that isn't recognized as RAM.
`ram_style` 속성은 RAM으로 인식되지 않는 항목에 적용됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: ram_style on a non-RAM signal
### P1: RAM이 아닌 신호의 ram_style

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: ram_style on non-RAM
attribute ram_style of ETMDABORT : signal is "block";  -- WARNING
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: remove attribute from non-RAM signals
-- Only apply ram_style to actual RAM arrays
```

---

## Fix Strategy
## 전략 수정

1. Apply `ram_style` only to a signal that is actually inferred as a memory (an addressable array) — remove it from scalar/vector signals.
1. 실제로 메모리(주소 지정 가능한 배열)로 추론되는 신호에만 'ram_style'을 적용하고 스칼라/벡터 신호에서는 제거하세요.
2. If you wanted the object to become a RAM, restructure it as an `array` indexed by an address with synchronous access so it is recognized.
2. 객체를 RAM으로 만들고 싶다면 동기 액세스가 가능한 주소로 인덱스된 '배열'로 재구성하여 인식되도록 하세요.
3. For non-memory signals you want to preserve/control, use `keep`/`dont_touch` instead of `ram_style`.
3. 보존/제어하려는 비메모리 신호의 경우 `ram_style` 대신 `keep`/`dont_touch`를 사용하세요.
4. Remove the ineffective attribute to clear the warning if no RAM was intended.
4. RAM이 의도되지 않은 경우 경고를 지우려면 유효하지 않은 속성을 제거하십시오.
