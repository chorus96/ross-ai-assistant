# 8-312: Ignoring Dynamic Assertion
# 8-312: 동적 어설션 무시

**Message:** `[Synth 8-312] ignoring unsynthesizable construct: dynamic assertion statement`
**메시지:** `[Synth 8-312] 합성할 수 없는 구문 무시: 동적 어설션 문`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

Dynamic assertions (`assert`) are simulation-only and ignored during synthesis.
동적 어설션('assert')은 시뮬레이션 전용이며 합성 중에는 무시됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Dynamic assertion in synthesizable code
### P1: 합성 가능한 코드의 동적 어설션

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: dynamic assertion in synthesizable code
assert (data != 0) else $error("zero");
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: remove or guard with translate_off
// synthesis translate_off
assert (data != 0);
// synthesis translate_on
```

---

## Fix Strategy
## 전략 수정

1. Wrap simulation-only assertions in `// synthesis translate_off` / `// synthesis translate_on` (or `` `ifndef SYNTHESIS ``) so they are excluded from synthesis.
1. 시뮬레이션 전용 어설션을 `// 종합 번역 오프` / `// 합성 번역 온`(또는 `` ifndef SYNTHESIS ``)으로 래핑하여 합성에서 제외되도록 합니다.
2. Prefer moving assertions into a separate bound checker module or the testbench, keeping synthesizable RTL clean.
2. 합성 가능한 RTL을 깨끗하게 유지하면서 어설션을 별도의 바운드 검사기 모듈이나 테스트 벤치로 이동하는 것을 선호합니다.
3. Use immediate/concurrent SVA assertions only in verification code; they have no hardware and are always ignored by synthesis.
3. 확인 코드에서만 즉시/동시 SVA 어설션을 사용하세요. 하드웨어가 없으며 합성에서는 항상 무시됩니다.
4. If the assertion encoded required behavior (e.g., a safety check), implement it as real logic (error flag, saturation) rather than relying on the assertion.
4. 어설션이 필수 동작(예: 안전 확인)을 인코딩한 경우 어설션에 의존하기보다는 실제 논리(오류 플래그, 포화)로 구현하세요.
