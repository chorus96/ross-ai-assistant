# 8-285: Failed Synthesizing Module
# 8-285: 합성 모듈 실패

**Message:** `[Synth 8-285] failed synthesizing module '!%1!'`
**메시지:** `[Synth 8-285] '!%1!' 모듈 합성에 실패했습니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-285] failed synthesizing module 'my_module' [/path/to/file.v:42]
```

---

## Root Cause
## 근본 원인

Synthesis of a specific module failed due to errors within that module.
해당 모듈 내의 오류로 인해 특정 모듈 합성에 실패했습니다.
This is typically a cascading error - earlier errors in the module caused synthesis to fail.
이는 일반적으로 계단식 오류입니다. 모듈의 이전 오류로 인해 합성이 실패했습니다.

---

## Diagnostic Steps
## 진단 단계

1. **Look for earlier errors** - This message usually follows other errors
1. **이전 오류를 찾아보세요** - 이 메시지는 일반적으로 다른 오류 다음에 나타납니다.
2. **Check the named module** - Open the module's source file
2. **이름이 지정된 모듈 확인** - 모듈의 소스 파일을 엽니다.
3. **Fix root cause errors first** - Address the actual syntax/semantic errors
3. **기본 원인 오류를 먼저 수정** - 실제 구문/의미 오류를 해결합니다.
4. **Re-run synthesis** - This error should disappear when root causes are fixed
4. **합성 다시 실행** - 근본 원인이 수정되면 이 오류는 사라져야 합니다.

---

## Common Root Causes
## 일반적인 근본 원인

| Earlier Error<br>이전 오류 | Typical Cause<br>일반적인 원인 |
|---------------|---------------|
| `[Synth 8-36]`<br>`[신디 8-36]` | Undeclared signal<br>선언되지 않은 신호 |
| `[Synth 8-439]`<br>`[신디사이저 8-439]` | Missing submodule<br>하위 모듈 누락 |
| `[Synth 8-549]`<br>`[신디사이저 8-549]` | Port width mismatch<br>포트 폭 불일치 |
| `[Synth 8-27]`<br>`[신디 8-27]` | Unsupported construct<br>지원되지 않는 구성 |

---

## Example
## 예

```
ERROR: [Synth 8-36] 'data_in' is not declared [my_module.v:25]
ERROR: [Synth 8-36] 'data_out' is not declared [my_module.v:30]
ERROR: [Synth 8-285] failed synthesizing module 'my_module' [my_module.v:1]
```

**Fix**: Address the `8-36` errors first by declaring `data_in` and `data_out`.
**수정**: 먼저 `data_in` 및 `data_out`을 선언하여 `8-36` 오류를 해결하세요.

---

## Fix Strategy
## 전략 수정

1. **Never fix 8-285 directly** — it is always a cascading error
1. **8-285를 직접 수정하지 마세요** — 항상 계단식 오류입니다.
2. Scroll UP in the log to find the FIRST error before 8-285
2. 로그에서 위로 스크롤하여 8-285 이전의 첫 번째 오류를 찾으세요.
3. Fix root cause errors in order from first to last
3. 근본 원인 오류를 처음부터 끝까지 순서대로 수정하세요.
4. Re-run synthesis — 8-285 disappears automatically
4. 합성 재실행 — 8-285가 자동으로 사라집니다.
5. If the only errors are 8-285 + another ID, fix the other ID
5. 유일한 오류가 8-285 + 다른 ID인 경우 다른 ID를 수정하세요.

**Common root cause pairs:**
**일반적인 근본 원인 쌍:**
- `8-439` (module not found) → `8-285` (module that instantiates it fails)
- `8-439`(모듈을 찾을 수 없음) → `8-285`(인스턴스화하는 모듈이 실패함)
- `8-690` (width mismatch) → `8-285` (containing module fails)
- `8-690`(너비 불일치) → `8-285`(모듈 포함 오류)
- `8-36` (undeclared) → `8-285` (containing module fails)
- `8-36`(선언되지 않음) → `8-285`(모듈 실패 포함)
- `8-549` (port width mismatch) → `8-285`
- `8-549`(포트 너비 불일치) → `8-285`

## Important: Width Mismatch in Mixed-Language Wrappers
## 중요: 혼합 언어 래퍼의 너비 불일치

A common pattern that causes 8-285 in mixed-language designs:
혼합 언어 디자인에서 8-285를 발생시키는 일반적인 패턴은 다음과 같습니다.

```vhdl
-- VHDL wrapper instantiates Verilog module
-- Verilog module: input signed in1;  (1-bit)
-- VHDL wrapper maps: std_logic_vector(1 downto 0) to it -> width mismatch!

-- This produces:
-- ERROR: [Synth 8-690] width mismatch... 
-- ERROR: [Synth 8-285] failed synthesizing module 'wrapper'
```

**Fix:** Correct the VHDL signal width to match Verilog port width, or add a
**수정:** VHDL 신호 폭을 Verilog 포트 폭과 일치하도록 수정하거나
conversion/resize in the port map.
포트 맵에서 변환/크기 조정.
