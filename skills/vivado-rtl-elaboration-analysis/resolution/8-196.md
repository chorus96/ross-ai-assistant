# 8-196: Conditional Expression Not Constant
# 8-196: 조건식이 상수가 아님

**Message:** `[Synth 8-196] conditional expression could not be resolved to a constant`
**메시지:** `[Synth 8-196] 조건식을 상수로 해석할 수 없습니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-196] conditional expression could not be resolved to a constant [/path/to/file.v:42]
```

---

## Root Cause
## 근본 원인

A conditional expression (`?:` ternary or `if` in certain contexts) that must be evaluated at compile time uses runtime signals instead of constants.
컴파일 시간에 평가해야 하는 조건식(`?:` 삼항 또는 특정 컨텍스트에서는 `if`)은 상수 대신 런타임 신호를 사용합니다.

---

## Where Constant Conditions Required
## 상수 조건이 필요한 경우

| Context<br>맥락 | Requires Constant<br>상수 필요 |
|---------|-------------------|
| Generate `if`<br>'만약' 생성 | Yes<br>예 |
| Parameter assignment<br>매개변수 할당 | Yes<br>예 |
| Array dimension<br>배열 차원 | Yes<br>예 |
| `localparam` RHS<br>`localparam` RHS | Yes<br>예 |

---

## Common Patterns
## 일반적인 패턴

### P1: Generate If with Signal
### P1: 신호로 If 생성

```verilog
// Before - signal in generate condition
wire enable;
generate
  if (enable)  // ERROR: not constant
    assign out = in1;
  else
    assign out = in2;
endgenerate

// After - use parameter
parameter ENABLE = 1;
generate
  if (ENABLE)
    assign out = in1;
  else
    assign out = in2;
endgenerate
```

### P2: Parameter with Runtime Expression
### P2: 런타임 표현식이 포함된 매개변수

```verilog
// Before - runtime value in parameter
input [3:0] sel;
localparam WIDTH = (sel == 0) ? 8 : 16;  // ERROR

// After - use constant
parameter SEL = 0;
localparam WIDTH = (SEL == 0) ? 8 : 16;
```

### P3: Array Size with Conditional
### P3: 조건부 배열 크기

```verilog
// Before - signal-dependent size
input mode;
reg [7:0] mem [(mode ? 256 : 128) - 1 : 0];  // ERROR

// After - constant-based size
parameter MODE = 1;
localparam DEPTH = MODE ? 256 : 128;
reg [7:0] mem [DEPTH - 1 : 0];
```

---

### P4: Genvar Loop with Non-Deterministic Condition
### P4: 비결정적 조건의 Genvar 루프

```verilog
// Before - genvar comparison that synthesis cannot resolve
for(genvar i = 1; i == 1; i++)   // ERROR: conditional not constant
begin
    my_mod inst[i](...);
end

for(genvar i = 2; i == 2; i++)   // ERROR: same pattern
begin
    my_mod inst2[i](...);
end

// After - replace with statically deterministic bounds
for(genvar i = 0; i < 1; i++)
begin
    my_mod inst[0](...);
end
```

**Important:** Check the ENTIRE file for ALL genvar loops with `==` conditions.
**중요:** `==` 조건이 있는 모든 genvar 루프에 대해 전체 파일을 확인하세요.
Multiple loops may use this pattern — fix ALL of them, not just the first one.
여러 루프에서 이 패턴을 사용할 수 있습니다. 첫 번째 루프뿐만 아니라 모든 루프를 수정하세요.

### P5: Tagged Union in Generate Context
### P5: 생성 컨텍스트의 태그된 Union

```verilog
// Before - tagged union variable in generate scope
union tagged packed { integer i; } var1;
for(genvar i = 1; i == 1; i++)
begin
    my_mod I1[i](.in1(var1), ...);
end

// After - remove generate, instantiate directly
my_mod I1(.in1(var1), ...);
```

## Fix Strategy
## 전략 수정

1. Replace runtime signals with parameters
1. 런타임 신호를 매개변수로 대체
2. Move conditional logic to runtime multiplexers
2. 조건부 논리를 런타임 멀티플렉서로 이동
3. Use `generate` with constant conditions only
3. 상수 조건에서만 '생성'을 사용하세요.
4. **Scan the ENTIRE file** for all genvar loops — fix every one, not just the first
4. **전체 파일을 스캔**하여 모든 genvar 루프를 확인하세요. 첫 번째 루프뿐만 아니라 모든 루프를 수정하세요.
5. Replace `i == N` genvar conditions with `i < 1` bounded loops
5. `i == N` genvar 조건을 `i < 1` 경계 루프로 교체
6. If a single instantiation is wrapped in a trivial generate, remove the generate entirely
6. 단일 인스턴스화가 사소한 생성으로 래핑된 경우 생성을 완전히 제거하십시오.

## Runtime Alternative
## 런타임 대안

```verilog
// If runtime selection needed, use mux instead of generate
wire [7:0] out;
assign out = enable ? in1 : in2;  // This works at runtime
```
