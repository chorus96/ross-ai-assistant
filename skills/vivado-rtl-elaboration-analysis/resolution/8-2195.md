# 8-2195: Signing on Unpacked Struct
# 8-2195: 압축 해제된 구조체에 서명

**Message:** `[Synth 8-2195] illegal usage of signing with unpacked struct/union type`
**메시지:** `[Synth 8-2195] 압축이 풀린 구조체/공용체 유형을 사용한 서명의 불법 사용`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A `signed` or `unsigned` qualifier is applied to an unpacked struct/union, which is not allowed.
'signed' 또는 'unsigned' 한정자는 압축이 풀린 구조체/공용체에 적용되며 이는 허용되지 않습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Signing qualifier on unpacked struct
### P1: 압축이 풀린 구조체의 서명 한정자

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: signed on unpacked struct
typedef struct {int a; int b;} signed my_t;  // ERROR
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: remove signing or use packed
typedef struct packed signed {logic [31:0] a, b;} my_t;  // packed OK
// Or remove signing:
typedef struct {int a; int b;} my_t;
```

---

## Fix Strategy
## 전략 수정

1. Apply `signed`/`unsigned` only to **packed** structs/unions — add the `packed` keyword if signed arithmetic on the whole struct is intended (`struct packed signed { ... }`).
1. **packed** 구조체/공용체에만 `signed`/`unsigned`를 적용합니다. 전체 구조체에 대한 부호 있는 산술이 의도된 경우(`struct Packed signed { ... }`)에는 `packed` 키워드를 추가합니다.
2. If the struct must stay unpacked, remove the signing qualifier entirely.
2. 구조체가 압축 해제된 상태로 유지되어야 하는 경우 서명 한정자를 완전히 제거하세요.
3. Ensure each member of a packed signed struct is itself a packed vector type (e.g., `logic [31:0]`), not `int`/unpacked members.
3. 압축된 서명된 구조체의 각 멤버가 `int`/언팩된 멤버가 아닌 압축된 벡터 유형(예: `logic [31:0]`)인지 확인하세요.
4. If only one field needs signed interpretation, drop struct-level signing and cast that field with `$signed(...)` where used.
4. 하나의 필드에만 서명된 해석이 필요한 경우 구조체 수준 서명을 삭제하고 해당 필드를 `$signed(...)`로 캐스팅하세요.
