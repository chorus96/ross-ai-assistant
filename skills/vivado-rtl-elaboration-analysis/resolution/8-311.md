# 8-311: Ignoring Non-Constant Initial
# 8-311: 상수가 아닌 초기값 무시

**Message:** `[Synth 8-311] ignoring non-constant assignment in initial block`
**메시지:** `[Synth 8-311] 초기 블록에서 상수가 아닌 할당을 무시합니다`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A non-constant assignment in an `initial` block is ignored during synthesis.
'초기' 블록의 상수가 아닌 할당은 합성 중에 무시됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Non-constant assignment in initial block
### P1: 초기 블록에 상수가 아닌 할당

**Problematic Code:**
**문제가 있는 코드:**
```diff
initial begin
  mem[0] = func(data);  // WARNING: non-constant ignored
end
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// Use constant values in initial blocks for synthesis
initial begin
  mem[0] = 8'h00;  // constant value
end
```

---

## Fix Strategy
## 전략 수정

1. Use only constant values for memory/register initialization in `initial` blocks intended for synthesis.
1. 합성용 `초기` 블록의 메모리/레지스터 초기화에는 상수 값만 사용하세요.
2. For ROM/RAM contents, use `$readmemh`/`$readmemb` (supported for memory init) or a parameterized constant array instead of computed expressions.
2. ROM/RAM 콘텐츠의 경우 계산된 표현식 대신 `$readmemh`/`$readmemb`(메모리 초기화에 지원됨) 또는 매개변수화된 상수 배열을 사용하세요.
3. Move any runtime computation out of `initial` and into reset logic — `always @(posedge clk)` with a synchronous/asynchronous reset that loads the required value.
3. 필요한 값을 로드하는 동기/비동기 재설정을 통해 런타임 계산을 '초기'에서 재설정 논리('항상 @(posedge clk)')로 이동합니다.
4. Confirm the ignored assignment was not providing required behavior; if it was, redesign it as proper reset or combinational logic.
4. 무시된 할당이 필수 동작을 제공하지 않았는지 확인하세요. 그렇다면 적절한 재설정 또는 조합 논리로 다시 설계하십시오.
