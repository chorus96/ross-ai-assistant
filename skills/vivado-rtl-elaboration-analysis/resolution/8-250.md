# 8-250: Disable Statement Scope Error
# 8-250: 문 범위 오류 비활성화

**Message:** `[Synth 8-250] disable statement must apply to a surrounding named block or a task`
**메시지:** `[Synth 8-250] 비활성화 문은 주변의 명명된 블록이나 작업에 적용되어야 합니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-250] disable statement must apply to a surrounding named block or a task [/path/to/file.v:42]
```

---

## Root Cause
## 근본 원인

The Verilog `disable` statement references a block or task that doesn't exist or isn't in the correct scope.
Verilog `disable` 문은 존재하지 않거나 올바른 범위에 없는 블록이나 작업을 참조합니다.
The `disable` statement can only disable:
`disable` 문은 다음만 비활성화할 수 있습니다.
- A surrounding named `begin-end` block
- 'begin-end' 블록이라는 이름의 주변
- A task that contains the disable statement
- 비활성화 문이 포함된 작업

---

## Common Patterns
## 일반적인 패턴

### P1: Unnamed Block
### P1: 이름이 없는 블록

```verilog
// Before - trying to disable unnamed block
always @(posedge clk) begin
  if (abort)
    disable;  // ERROR: no block name
end

// After - name the block
always @(posedge clk) begin : main_block
  if (abort)
    disable main_block;
end
```

### P2: Wrong Block Name
### P2: 잘못된 블록 이름

```verilog
// Before - referencing non-existent block
always @(posedge clk) begin : loop_block
  if (done)
    disable other_block;  // ERROR: other_block doesn't exist
end

// After - use correct name
always @(posedge clk) begin : loop_block
  if (done)
    disable loop_block;
end
```

### P3: Block Not Surrounding
### P3: 블록이 주변에 없음

```verilog
// Before - disable block from outside
always @(posedge clk) begin : block_a
  // ...
end

always @(posedge clk) begin : block_b
  if (stop)
    disable block_a;  // ERROR: block_a not surrounding
end

// After - disable must be inside the block
always @(posedge clk) begin : block_a
  if (stop)
    disable block_a;  // CORRECT: inside block_a
end
```

### P4: Task Disable
### P4: 작업 비활성화

```verilog
// Correct usage in task
task my_task;
  begin
    if (abort)
      disable my_task;  // OK: disabling containing task
    // ... rest of task
  end
endtask
```

## Synthesis Consideration
## 합성 고려사항

Note: `disable` is often not synthesizable.
참고: `disable`은 합성할 수 없는 경우가 많습니다.
Consider using alternative control flow:
대체 제어 흐름을 사용해 보세요.

```verilog
// Alternative - use return or state machine
always @(posedge clk) begin
  if (!abort) begin
    // main logic only when not aborted
  end
end
```

---

## Fix Strategy
## 전략 수정

1. Name the enclosing `begin`/`end` block (`begin : label`) and `disable label;` only that surrounding block, or `disable` the containing task.
1. 둘러싸는 `begin`/`end` 블록의 이름을 지정하고(`begin : label`) `disable label`을 지정합니다. 해당 주변 블록만 사용하거나 포함된 작업을 `disable`합니다.
2. Verify the target label exists and lexically surrounds the `disable`; you cannot disable a sibling or outer block from elsewhere.
2. 대상 라벨이 존재하고 `disable`을 어휘적으로 둘러싸는지 확인하세요. 다른 곳에서는 형제 블록이나 외부 블록을 비활성화할 수 없습니다.
3. For synthesis, replace `disable`-based early-exit with equivalent guarded logic (an `if` around the body, or an FSM), since `disable` is generally not synthesizable.
3. 합성의 경우 'disable' 기반 조기 종료를 동등한 보호 논리(본체 주변의 'if' 또는 FSM)로 바꾸십시오. 'disable'은 일반적으로 합성할 수 없기 때문입니다.
4. Re-run elaboration to confirm the `8-250` message is cleared.
4. '8-250' 메시지가 지워졌는지 확인하려면 정교화를 다시 실행하세요.
