# 8-983: Module Instantiation in Compilation Scope
# 8-983: 컴파일 범위의 모듈 인스턴스화

**Message:** `[Synth 8-983] module instantiations in compilation scope are not allowed`
**메시지:** `[Synth 8-983] 컴파일 범위의 모듈 인스턴스화는 허용되지 않습니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A module is instantiated at file scope, outside any module.
모듈은 모듈 외부의 파일 범위에서 인스턴스화됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Instantiation at file/compilation scope
### P1: 파일/컴파일 범위에서 인스턴스화

**Problematic Code:**
**문제가 있는 코드:**
```diff
// At file scope (not inside any module):
my_mod inst(...);  // ERROR
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
module top;
  my_mod inst(...);  // inside a module
endmodule
```

---

## Fix Strategy
## 전략 수정

1. Move the instantiation inside a `module ... endmodule` (or the appropriate design unit) — instances are not allowed at file/compilation scope.
1. 인스턴스화를 `module ... endmodule`(또는 적절한 디자인 단위) 내부로 이동합니다. 인스턴스는 파일/컴파일 범위에서 허용되지 않습니다.
2. If this file was meant to be a testbench top, wrap the instantiations in a top-level `module tb; ... endmodule`.
2. 이 파일이 테스트벤치 상단으로 의도된 경우 인스턴스화를 최상위 `module tb; ... 엔드모듈`.
3. Check for a missing/misplaced `endmodule` above that accidentally closed the enclosing module early, leaving the instance at file scope.
3. 위의 누락/잘못 배치된 'endmodule'이 실수로 포함 모듈을 조기에 닫아 인스턴스가 파일 범위에 남아 있는지 확인하세요.
4. Verify the file is being compiled as design source (not as an include fragment) if instances were expected to be inside an outer module.
4. 인스턴스가 외부 모듈 내부에 있을 것으로 예상되는 경우 파일이 디자인 소스(포함 조각이 아님)로 컴파일되고 있는지 확인하십시오.
