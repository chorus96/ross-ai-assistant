# 8-2913: Unsupported Dual Port BRAM Template
# 8-2913: 지원되지 않는 듀얼 포트 BRAM 템플릿

**Message:** `[Synth 8-2913] Unsupported Dual Port Block-RAM template for !%1!`
**메시지:** `[Synth 8-2913] !%1!에 대해 지원되지 않는 듀얼 포트 블록 RAM 템플릿!`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

## Root Cause
## 근본 원인

The RTL coding pattern doesn't match a supported dual-port Block RAM template.
RTL 코딩 패턴이 지원되는 이중 포트 블록 RAM 템플릿과 일치하지 않습니다.

## 일반적인 패턴

### P1: 비템플릿 듀얼 포트 RAM 설명

**문제가 있는 코드:**

```diff
// Before: unsupported BRAM template
// Vivado can't infer dual-port BRAM from this coding style
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: follow UG901 BRAM coding guidelines

// - Match Vivado's supported BRAM templates

```

## Fix Strategy
## 전략 수정

1. Rewrite the dual-port RAM to match a Vivado-supported template (see UG901 "RAM HDL Coding Techniques") — typically one clocked process per port.
1. Vivado 지원 템플릿(UG901 "RAM HDL 코딩 기술" 참조)과 일치하도록 듀얼 포트 RAM을 다시 작성합니다. 일반적으로 포트당 하나의 클록 프로세스입니다.
2. Use **synchronous** reads (registered output) on each port; asynchronous reads block BRAM inference.
2. 각 포트에서 **동기** 읽기(등록된 출력)를 사용합니다. 비동기식 읽기는 BRAM 추론을 차단합니다.
3. Handle the read/write collision behavior explicitly (read-first / write-first / no-change) as the template requires.
3. 템플릿에서 요구하는 대로 읽기/쓰기 충돌 동작을 명시적으로(읽기 우선/쓰기 우선/변경 없음) 처리합니다.
4. If the shape truly cannot map to BRAM, instantiate a Block Memory Generator IP or accept distributed RAM with the appropriate `ram_style`.
4. 모양이 실제로 BRAM에 매핑될 수 없는 경우 블록 메모리 생성기 IP를 인스턴스화하거나 적절한 `ram_style`을 사용하여 분산 RAM을 허용합니다.
