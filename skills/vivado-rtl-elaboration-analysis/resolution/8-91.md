# 8-91: Ambiguous Clock in Event Control
# 8-91: 이벤트 제어의 모호한 시계

**Message:** `[Synth 8-91] ambiguous clock in event control`
**메시지:** `[Synth 8-91] 이벤트 제어에 시계가 모호합니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-91] ambiguous clock in event control [/path/to/file.v:42]
```

---

## Root Cause
## 근본 원인

The sensitivity list of an always block has multiple clock edges or conditions that make it unclear which signal is the clock.
항상 블록의 민감도 목록에는 어떤 신호가 클럭인지 불분명하게 만드는 여러 클럭 에지 또는 조건이 있습니다.
Synthesis requires unambiguous clock identification.
합성에는 명확한 시계 식별이 필요합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Multiple Clocks in Same Block
### P1: 동일한 블록에 여러 개의 클록

```verilog
// Before - two clocks in same block
always @(posedge clk1 or posedge clk2) begin  // ERROR: ambiguous
  if (clk1)
    data1 <= in1;
  else
    data2 <= in2;
end
```

```diff
// After - separate blocks for each clock
+ always @(posedge clk1) begin
+   data1 <= in1;
+ end
+ 
+ always @(posedge clk2) begin
+   data2 <= in2;
+ end
```

### P2: Clock Mixed with Combinational Signals
### P2: 조합 신호와 혼합된 클록

```verilog
// Before - mixing clock edge with level-sensitive
always @(posedge clk or data_in) begin  // ERROR: ambiguous
  ...
end
```

```diff
// After - separate sequential and combinational
+ always @(posedge clk) begin
+   // Sequential logic
+ end
+ 
+ always @(*) begin
+   // Combinational logic
+ end
```

### P3: Ambiguous Reset Polarity
### P3: 모호한 재설정 극성

```verilog
// Before - unclear which is clock vs reset
always @(posedge sig1 or posedge sig2) begin
  // Both are posedge - which is clock?
end
```

```diff
// After - use async reset with clear polarity
+ always @(posedge clk or negedge rst_n) begin
+   if (!rst_n)
+     q <= 0;
+   else
+     q <= d;
+ end
```

---

## Best Practices
## 모범 사례

1. One clock per always block
1. 항상 블록당 하나의 시계
2. Use `negedge` for async reset when using `posedge` clock
2. `posedge` 시계를 사용할 때 비동기 재설정을 위해 `negedge`를 사용하세요.
3. Keep combinational logic in separate `always @(*)` blocks
3. 별도의 `항상 @(*)` 블록에 조합 논리를 유지합니다.
4. Use clear naming: `clk`, `rst`, `rst_n`
4. 명확한 이름 지정 사용: `clk`, `rst`, `rst_n`

---

## Fix Strategy
## 전략 수정

1. Keep exactly one clock edge per sequential `always` block; split multi-clock logic into one block per clock domain.
1. 순차적 `always` 블록당 정확히 하나의 클럭 에지를 유지합니다. 다중 클럭 로직을 클럭 도메인당 하나의 블록으로 분할합니다.
2. In the sensitivity list, allow only the clock edge plus (optionally) one async-reset edge — remove level-sensitive or combinational signals.
2. 민감도 목록에서 클럭 에지와 하나의 비동기 재설정 에지(선택적으로)만 허용합니다. 레벨에 민감한 신호 또는 조합 신호를 제거합니다.
3. Give reset a clear polarity paired with the clock (e.g., `always @(posedge clk or negedge rst_n)`), and handle the reset branch first.
3. 클록과 쌍을 이루는 명확한 극성을 재설정하고(예: `always @(posedge clk 또는 negedge rst_n)`) 재설정 분기를 먼저 처리하세요.
4. Move combinational logic into a separate `always @(*)` block, then re-run elaboration to confirm `8-91` is cleared.
4. 조합 논리를 별도의 '항상 @(*)' 블록으로 옮긴 다음 정교화를 다시 실행하여 '8-91'이 지워졌는지 확인하세요.
