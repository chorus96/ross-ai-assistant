# 8-7213: Expression Doesn't Match Clock Edges
# 8-7213: 표현식이 시계 에지와 일치하지 않습니다.

**Message:** `[Synth 8-7213] Expression condition using operand '!%1!' does not match with the corresponding edges used in event control`
**메시지:** `[Synth 8-7213] 피연산자 '!%1!'을 사용한 표현식 조건 이벤트 제어에 사용된 해당 에지와 일치하지 않습니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

An always block condition uses a signal in an expression that doesn't match the declared clock edges.
항상 차단 조건은 선언된 클럭 에지와 일치하지 않는 표현식의 신호를 사용합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Reset condition doesn't match the edge
### P1: 재설정 조건이 에지와 일치하지 않습니다.

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: condition doesn't match edge
always @(posedge clk or negedge rst)
  if (HRESETn)  // ERROR: using HRESETn but edge is on rst
    ...
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: match condition to edges
always @(posedge clk or negedge rst_n)
  if (!rst_n) out <= 0;  // rst_n matches negedge
  else out <= data;
```

---

## Fix Strategy
## 전략 수정

1. Make the `if`/`else` reset conditions reference the **same** signals (and polarity) used in the sensitivity-list edges — e.g., `@(posedge clk or negedge rst_n)` with `if (!rst_n)`.
1. `if`/`else` 재설정 조건이 민감도 목록 에지에 사용된 **동일한** 신호(및 극성)를 참조하도록 만듭니다(예: `if (!rst_n)`와 함께 `@(posedge clk 또는 negedge rst_n)`).
2. If reset is active-low on `negedge rst_n`, test `!rst_n`; for active-high on `posedge rst`, test `rst`.
2. 'negedge rst_n'에서 재설정이 액티브 로우인 경우 '!rst_n'을 테스트하세요. 'posedge rst'에서 활성 높음의 경우 'rst'를 테스트하세요.
3. Do not mix an edge on one signal with a condition on a differently-named signal (e.g., edge on `rst` but test `HRESETn`).
3. 한 신호의 에지를 이름이 다른 신호의 조건과 혼합하지 마십시오(예: `rst`의 에지이지만 `HRESETn` 테스트).
4. Keep exactly one clock and (optionally) one async reset in the sensitivity list and mirror them in the branch conditions.
4. 민감도 목록에 정확히 하나의 클럭과 하나의 비동기 재설정을 유지하고 이를 분기 조건에 미러링합니다.
