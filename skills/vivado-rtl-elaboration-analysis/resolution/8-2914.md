# 8-2914: Unsupported RAM Template
# 8-2914: 지원되지 않는 RAM 템플릿

**Message:** `[Synth 8-2914] Unsupported RAM template`
**메시지:** `[Synth 8-2914] 지원되지 않는 RAM 템플릿`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

The VHDL RAM description doesn't match any supported RAM inference template.
VHDL RAM 설명이 지원되는 RAM 추론 템플릿과 일치하지 않습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Non-template RAM description (VHDL)
### P1: 비템플릿 RAM 설명(VHDL)

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: unsupported RAM coding style
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: follow UG901 RAM coding guidelines
-- - Use process with clock for synchronous read/write
-- - Match Vivado's supported RAM templates
-- - See UG901 'RAM HDL Coding Techniques'
```

---

## Fix Strategy
## 전략 수정

1. Restructure the RAM to a Vivado inference template (UG901): a clocked `process` performing synchronous write and synchronous (registered) read on the memory array.
1. RAM을 Vivado 추론 템플릿(UG901)으로 재구성합니다. 메모리 어레이에서 동기 쓰기 및 동기(등록) 읽기를 수행하는 클럭킹 '프로세스'입니다.
2. Use a proper memory type — an `array (0 to DEPTH-1) of std_logic_vector(...)` indexed by an address.
2. 적절한 메모리 유형(주소로 색인화된 `std_logic_Vector(...)의 배열(0 ~ DEPTH-1)`)을 사용하세요.
3. Avoid asynchronous reads and mixed read/write styles that defeat inference.
3. 추론을 방해하는 비동기 읽기 및 혼합 읽기/쓰기 스타일을 피하세요.
4. If the description still will not infer, use the Block Memory Generator IP or select `ram_style`/`rom_style` to force the intended implementation.
4. 설명이 여전히 추론되지 않으면 블록 메모리 생성기 IP를 사용하거나 `ram_style`/`rom_style`을 선택하여 의도한 구현을 강제합니다.
