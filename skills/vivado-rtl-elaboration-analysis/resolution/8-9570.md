# 8-9570: Packed vs Unpacked Case Comparison
# 8-9570: 포장된 케이스와 포장되지 않은 케이스 비교

**Message:** `[Synth 8-9570] illegal case item comparison of a packed type with an unpacked type`
**메시지:** `[Synth 8-9570] 패킹된 유형과 언팩된 유형의 불법 사례 항목 비교`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A case statement compares packed and unpacked types.
Case 문은 압축된 유형과 압축되지 않은 유형을 비교합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Packed vs unpacked case comparison
### P1: 포장된 케이스와 포장되지 않은 케이스 비교

**Problematic Code:**
**문제가 있는 코드:**
```diff
case(packed_sig) matches
  unpacked_val: ...  // ERROR: type mismatch
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
case(packed_sig)
  packed_val: ...  // use matching types
```

---

## Fix Strategy
## 전략 수정

1. Make the case selector and every case item the **same** packed-vs-unpacked kind and type.
1. 케이스 선택기와 모든 케이스 항목을 **동일한** 포장 및 비포장 종류와 유형으로 만듭니다.
2. Compare packed vectors against packed literals; do not mix a packed selector with an unpacked value.
2. 압축된 벡터를 압축된 리터럴과 비교합니다. 압축된 선택기와 압축되지 않은 값을 혼합하지 마세요.
3. If comparing structs/arrays, ensure both sides are the same (packed) type, or compare field/element-wise.
3. 구조체/배열을 비교하는 경우 양쪽이 동일한(패킹된) 유형인지 확인하거나 필드/요소별로 비교하십시오.
4. Convert one side explicitly (pack/unpack via streaming/concatenation) so both match.
4. 한쪽을 명시적으로 변환(스트리밍/연결을 통해 압축/압축 해제)하여 둘 다 일치하도록 합니다.
