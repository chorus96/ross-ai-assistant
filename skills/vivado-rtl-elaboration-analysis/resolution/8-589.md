# 8-589: Replacing Case Equality
# 8-589: 대소문자 동일 교체

**Message:** `[Synth 8-589] replacing case/wildcard equality operator === with logical equality`
**메시지:** `[Synth 8-589] 대소문자/와일드카드 동등 연산자 ===를 논리적 동등으로 대체`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

Vivado replaces `===` (4-state) with `==` (2-state) for synthesis.
Vivado는 합성을 위해 `===`(4-상태)를 `==`(2-상태)로 대체합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Case-equality operator used in synthesizable code
### P1: 합성 가능한 코드에 사용되는 대소문자 동등 연산자

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: case equality (4-state)
if (a === b)  // WARNING: replaced with ==
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: use == directly
if (a == b)  // 2-state equality for synthesis
```

---

## Fix Strategy
## 전략 수정

1. This is informational — synthesis replaces `===`/`!==` (4-state) with `==`/`!=` (2-state) because hardware has no `x`/`z`.
1. 이는 정보 제공용입니다. 하드웨어에 `x`/`z`가 없기 때문에 합성은 `===`/`!==`(4-상태)를 `==`/`!=`(2-상태)로 대체합니다.
1. Change the source to `==`/`!=` to make the intent explicit and silence the warning.
1. 의도를 명시적으로 만들고 경고를 무시하려면 소스를 `==`/`!=`로 변경하세요.
2. If you were using `===` to detect `x`/`z`, that check has no hardware meaning — remove it or move it to simulation-only code (`translate_off`).
2. `x`/`z`를 감지하기 위해 `===`를 사용했다면 해당 검사는 하드웨어 의미가 없습니다. 이를 제거하거나 시뮬레이션 전용 코드(`translate_off`)로 이동하세요.
3. For don't-care comparisons against constants with `?`, use `casez`/wildcard-equality intentionally instead of relying on `===`.
3. `?`를 사용하는 상수에 대한 무상 비교의 경우 `===`에 의존하는 대신 의도적으로 `casez`/wildcard-equality를 사용하십시오.
4. Confirm the 2-state behavior matches your intent, since `x`/`z` operands collapse to 0/1 in synthesis.
4. `x`/`z` 피연산자가 합성에서 0/1로 축소되므로 2상태 동작이 의도와 일치하는지 확인하세요.
