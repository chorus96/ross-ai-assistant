# 8-613: Shared Variable as Local
# 8-613: 로컬로서의 공유변수

**Message:** `[Synth 8-613] shared variable will be implemented as local`
**메시지:** `[Synth 8-613] 공유 변수가 로컬로 구현됩니다`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A VHDL shared variable is implemented as local to the architecture (not shared across processes).
VHDL 공유 변수는 아키텍처에 대해 로컬로 구현됩니다(프로세스 간에 공유되지 않음).

---

## Common Patterns
## 일반적인 패턴

### P1: Shared variable used across processes
### P1: 프로세스 전반에 걸쳐 사용되는 공유 변수

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: shared variable
shared variable sv : integer;  -- WARNING: local
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: use signal for inter-process communication
signal sv : integer;
```

---

## Fix Strategy
## 전략 수정

1. Use a `signal` (not a shared variable) for any value that must be visible across processes — synthesis implements shared variables as process-local, which will not behave as intended.
1. 프로세스 전반에 걸쳐 표시되어야 하는 모든 값에 '신호'(공유 변수 아님)를 사용하세요. 합성은 공유 변수를 프로세스 로컬로 구현하므로 의도한 대로 작동하지 않습니다.
2. If the shared variable was used for accumulation within one process, keep it as a `variable` local to that process; that is legal and synthesizable.
2. 공유 변수가 하나의 프로세스 내에서 누적에 사용된 경우 해당 프로세스에 대한 '변수'로 유지하십시오. 그것은 합법적이고 종합 가능합니다.
3. Drive cross-process state through signals with a single, well-defined driver to avoid multiple-driver issues.
3. 다중 드라이버 문제를 방지하기 위해 잘 정의된 단일 드라이버를 사용하여 신호를 통해 프로세스 간 상태를 구동합니다.
4. Confirm the design does not rely on simulation-only shared-variable ordering semantics.
4. 설계가 시뮬레이션 전용 공유 변수 순서 의미 체계에 의존하지 않는지 확인합니다.
