# 8-10440: Unit Not Yet Analyzed
# 8-10440: 아직 분석되지 않은 장치

**Message:** `[Synth 8-10440] Unit is not yet analyzed`
**메시지:** `[Synth 8-10440] 장치가 아직 분석되지 않았습니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-10440] Unit is not yet analyzed [/path/to/file:NN]
```

---

## Root Cause
## 근본 원인

A VHDL package or entity referenced via `use` or instantiation has not been compiled/analyzed yet, often due to incorrect compile order or missing library.
'사용' 또는 인스턴스화를 통해 참조된 VHDL 패키지 또는 엔터티가 아직 컴파일/분석되지 않았습니다. 이는 종종 잘못된 컴파일 순서 또는 누락된 라이브러리로 인해 발생합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Unit referenced before analysis
### P1: 해석 전 참조된 단위

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: referencing unanalyzed package
library work;
use work.all;
package inst_pack1 is new pack generic map(bit_vector); -- ERROR: 'pack' not analyzed
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: ensure correct compile order
-- Compile pack.vhdl BEFORE files that reference it
-- In run.files or TCL: read_vhdl pack.vhdl must come first
```

---

## Fix Strategy
## 전략 수정

1. Compile the referenced package/entity before the file that uses it (correct analysis/file order).
1. 참조된 패키지/엔티티를 사용하는 파일 전에 컴파일하십시오(올바른 분석/파일 순서).
2. Ensure it is analyzed into the expected library and referenced with the right name/prefix.
2. 예상 라이브러리로 분석되고 올바른 이름/접두어로 참조되는지 확인하십시오.
3. Check `read_vhdl`/fileset order in the Tcl flow so dependencies come first.
3. 종속성이 먼저 나오도록 Tcl 흐름에서 `read_vhdl`/fileset 순서를 확인하세요.
4. Fix typos in the unit/library name and confirm the library is declared/mapped.
4. 유닛/라이브러리 이름의 오타를 수정하고 라이브러리가 선언/매핑되었는지 확인하세요.
