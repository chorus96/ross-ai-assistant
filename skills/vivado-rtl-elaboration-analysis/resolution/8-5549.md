# 8-5549: Floating Point Exception
# 8-5549: 부동 소수점 예외

**Message:** `[Synth 8-5549] floating point exception`
**메시지:** `[Synth 8-5549] 부동 소수점 예외`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

An arithmetic operation in VHDL elaboration causes a floating point exception (divide by zero, overflow).
VHDL 정교화의 산술 연산으로 인해 부동 소수점 예외(0으로 나누기, 오버플로)가 발생합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Divide-by-zero in a generic computation
### P1: 일반 계산에서 0으로 나누기

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: division by zero in generic computation
generic (N : integer := 0);
constant RATIO : integer := 100 / N;  -- ERROR if N=0
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: guard against division by zero
constant RATIO : integer := 100 / maximum(N, 1);  -- avoid /0
```

---

## Fix Strategy
## 전략 수정

1. Guard compile-time computations against divide-by-zero and overflow — clamp divisors (`100 / maximum(N, 1)`) or add generate/assert checks on generic values.
1. 0으로 나누기 및 오버플로로부터 컴파일 시간 계산을 보호합니다. 제수(`100 / maximum(N, 1)`)를 고정하거나 일반 값에 생성/어설션 검사를 추가합니다.
2. Give generics safe, non-zero defaults and validate overrides at instantiation.
2. 제네릭에 안전하고 0이 아닌 기본값을 제공하고 인스턴스화 시 재정의를 검증합니다.
3. Keep intermediate results within `integer` range (2^31-1); use wider types or restructure the math if they can overflow.
3. 중간 결과를 '정수' 범위(2^31-1) 내로 유지합니다. 더 넓은 유형을 사용하거나 오버플로될 수 있는 경우 수학을 재구성하십시오.
4. Add an elaboration-time assertion (`assert N > 0 report "..." severity failure;`) so illegal configurations fail with a clear message instead of a floating-point exception.
4. 부동 소수점 예외 대신 명확한 메시지와 함께 잘못된 구성이 실패하도록 정교화 시간 어설션(`assert N > 0 보고 "..." 심각도 실패;`)을 추가합니다.
