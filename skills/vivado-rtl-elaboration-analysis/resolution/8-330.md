# 8-330: inout connections inferred for interface port
# 8-330: 인터페이스 포트에 대한 입력 연결이 추론됨

**Message:** `[Synth 8-330] inout connections inferred for interface port 'intf' with no modport`
**메시지:** `[Synth 8-330] modport가 없는 인터페이스 포트 'intf'에 대해 추론된 입력 연결`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A SystemVerilog interface is connected to a module port without specifying a
SystemVerilog 인터페이스는 지정하지 않고 모듈 포트에 연결됩니다.
modport.
모드포트.
With no modport to define signal directions, Vivado cannot infer input
신호 방향을 정의하는 모드 포트가 없으면 Vivado는 입력을 추론할 수 없습니다.
vs. output and defaults every interface signal to `inout`, which is usually not
대 출력이며 모든 인터페이스 신호의 기본값은 'inout'입니다. 일반적으로 그렇지 않습니다.
what the design intends.
디자인이 의도하는 바.

## Common Patterns
## 일반적인 패턴

### P1: Interface port declared without a modport
### P1: modport 없이 선언된 인터페이스 포트

**Problematic Code:**
**문제가 있는 코드:**
```systemverilog
interface my_if;
  logic [7:0] data;
  logic       valid;
endinterface

module sub2(my_if intf);          // no modport -> inout inferred
  assign intf.valid = ...;
endmodule
```

**Fix — define modports and use them on the port:**
**수정 — modport를 정의하고 포트에서 사용:**
```systemverilog
interface my_if;
  logic [7:0] data;
  logic       valid;
  modport producer (output data, output valid);
  modport consumer (input  data, input  valid);
endinterface

module sub2(my_if.producer intf); // directions now defined
  assign intf.valid = ...;
endmodule
```

### P2: Connection selects the modport at instantiation
### P2: 연결은 인스턴스화 시 modport를 선택합니다.

**Fix — pass the correct modport view when connecting:**
**수정 — 연결할 때 올바른 modport 보기를 전달합니다.**
```systemverilog
my_if bus();
sub2 u2(.intf(bus.producer));
consumer_mod u3(.intf(bus.consumer));
```

## Fix Strategy
## 전략 수정

1. Add explicit `modport` definitions to the interface that declare each signal's direction (`input`/`output`).
1. 각 신호의 방향(`input`/`output`)을 선언하는 인터페이스에 명시적인 `modport` 정의를 추가합니다.
2. Reference the modport in the module port declaration, e.g.
2. 모듈 포트 선언에서 modport를 참조하세요.
2. `module m(my_if.producer intf);`, so directions are defined instead of defaulting to `inout`.
2. `module m(my_if.producer intf);`이므로 `inout`을 기본값으로 설정하는 대신 방향이 정의됩니다.
3. When instantiating, connect the matching modport view (`.intf(bus.producer)` / `.intf(bus.consumer)`) to the producer and consumer sides.
3. 인스턴스화할 때 일치하는 모드포트 보기(`.intf(bus.producer)` / `.intf(bus.consumer)`)를 생산자 측과 소비자 측에 연결합니다.
4. If a true bidirectional connection is intended, keep it modport-less deliberately and document it; otherwise always specify a modport to avoid unintended `inout` inference.
4. 진정한 양방향 연결을 의도한다면 의도적으로 모드포트 없이 유지하고 문서화하십시오. 그렇지 않으면 의도하지 않은 `inout` 추론을 피하기 위해 항상 modport를 지정하십시오.
