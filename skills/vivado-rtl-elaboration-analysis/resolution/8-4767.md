# 8-4767: RAM in Registers
# 8-4767: 레지스터의 RAM

**Message:** `[Synth 8-4767] Trying to implement RAM in registers`
**메시지:** `[Synth 8-4767] 레지스터에 RAM을 구현하려고 합니다.`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

RAM is being implemented in registers instead of Block RAM — may cause resource issues.
RAM이 블록 RAM 대신 레지스터에서 구현되고 있어 리소스 문제가 발생할 수 있습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: RAM implemented in registers
### P1: 레지스터에 구현된 RAM

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- WARNING: RAM implemented as registers (may be large)
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- Force block RAM:
attribute ram_style : string;
attribute ram_style of RAM_reg : signal is "block";
-- Or check UG901 RAM templates
```

---

## Fix Strategy
## 전략 수정

1. If the memory should be Block RAM, apply `ram_style = "block"` (attribute) and code it with a synchronous (registered) read so it maps to BRAM.
1. 메모리가 블록 RAM이어야 하는 경우 `ram_style = "block"`(속성)을 적용하고 동기(등록된) 읽기로 코딩하여 BRAM에 매핑합니다.
2. Asynchronous reads or unusual read/write patterns force register/LUT implementation — restructure to a supported UG901 template.
2. 비동기식 읽기 또는 비정상적인 읽기/쓰기 패턴으로 인해 레지스터/LUT 구현이 강제되며 지원되는 UG901 템플릿으로 재구성됩니다.
3. If registers are acceptable (small memory), no action is needed — but confirm the resource/timing cost.
3. 레지스터가 허용 가능한 경우(작은 메모리) 조치가 필요하지 않지만 리소스/타이밍 비용을 확인하십시오.
4. For large memories, prefer BRAM to avoid excessive flip-flop usage; verify the mapping in the synthesis report.
4. 대용량 메모리의 경우 과도한 플립플롭 사용을 피하기 위해 BRAM을 선호합니다. 종합 보고서에서 매핑을 확인하세요.
