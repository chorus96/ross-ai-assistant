# 8-98: Array of Blackboxes
# 8-98: 블랙박스 배열

**Message:** `[Synth 8-98] array of blackboxes: assuming all ports are one bit`
**메시지:** `[Synth 8-98] 블랙박스 배열: 모든 포트가 1비트라고 가정`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

An array of blackbox instances assumes all ports are 1-bit wide.
블랙박스 인스턴스 배열은 모든 포트의 너비가 1비트라고 가정합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Instance array of a black box
### P1: 블랙박스의 인스턴스 배열

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: blackbox instance array
(* black_box *) my_mod inst[3:0](...);  // WARNING: assuming 1-bit ports
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: provide explicit port widths via stub
module my_mod(
  input [7:0] data,  // explicit widths
  output [7:0] out
);
endmodule
```

---

## Fix Strategy
## 전략 수정

1. Provide a stub module declaration with **explicit port widths** so the tool knows the real bus sizes instead of assuming 1-bit ports.
1. **명시적 포트 너비**가 포함된 스텁 모듈 선언을 제공하면 도구가 1비트 포트를 가정하는 대신 실제 버스 크기를 알 수 있습니다.
2. Prefer instantiating a real (non-blackbox) module when the RTL is available, so widths are checked.
2. RTL을 사용할 수 있는 경우 실제(블랙박스가 아닌) 모듈을 인스턴스화하여 너비를 확인하는 것이 좋습니다.
3. If the black box is intentional, give it a complete `(* black_box *)` stub with the full, correctly-sized port list.
3. 블랙박스가 의도적인 경우 전체 `(* black_box *)` 스텁과 올바른 크기의 전체 포트 목록을 제공하세요.
4. When port widths matter, avoid instance arrays of black boxes — instantiate each block individually with explicit named connections so widths are unambiguous.
4. 포트 너비가 중요한 경우 블랙박스의 인스턴스 배열을 피하십시오. 너비가 모호하지 않도록 명시적으로 명명된 연결을 사용하여 각 블록을 개별적으로 인스턴스화하십시오.
