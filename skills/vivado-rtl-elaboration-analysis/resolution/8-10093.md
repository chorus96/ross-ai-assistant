# 8-10093: Type Mismatch with String Literal
# 8-10093: 문자열 리터럴과 유형 불일치

**Message:** `[Synth 8-10093] type does not match with a string literal`
**메시지:** `[Synth 8-10093] 유형이 문자열 리터럴과 일치하지 않습니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-10093] type does not match with a string literal [/path/to/file:NN]
```

---

## Root Cause
## 근본 원인

A VHDL `report` clause or string context expects a string type but receives a different type, or a PSL directive uses syntax not supported by synthesis.
VHDL `report` 절 또는 문자열 컨텍스트는 문자열 유형을 예상하지만 다른 유형을 수신하거나 PSL 지시문이 합성에서 지원되지 않는 구문을 사용합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: PSL directive in synthesizable RTL
### P1: 합성 가능한 RTL의 PSL 지시문

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Before: PSL directive with report clause (not synthesizable)
asum2 : assume_guarantee always(prop) report "Property failed";
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- After: remove PSL directives (simulation-only)
-- PSL assume_guarantee is not synthesizable — remove or guard with translate_off
-- synthesis translate_off
-- asum2 : assume_guarantee always(prop) report "Property failed";
-- synthesis translate_on
```

---

## Fix Strategy
## 전략 수정

1. PSL directives (`assume_guarantee`, `assert`, ...) are simulation/verification-only — remove them from synthesizable RTL or guard with `-- synthesis translate_off/on`.
1. PSL 지시문(`assume_guarantee`, `assert`, ...)은 시뮬레이션/검증 전용입니다. 이를 합성 가능한 RTL에서 제거하거나 `-- 합성translate_off/on`으로 보호하세요.
2. Move formal/PSL properties into a bound verification unit, not the synthesized design.
2. 형식/PSL 속성을 합성된 디자인이 아닌 바인딩된 검증 단위로 이동합니다.
3. If a `report` string type mismatch triggered this, ensure the reported expression is a string type in simulation code.
3. `report` 문자열 유형 불일치로 인해 이 문제가 발생한 경우 보고된 표현식이 시뮬레이션 코드에서 문자열 유형인지 확인하세요.
4. Keep the synthesized path free of PSL so no string-literal type mismatch arises.
4. 문자열 리터럴 유형 불일치가 발생하지 않도록 합성 경로에 PSL이 없도록 유지하십시오.
