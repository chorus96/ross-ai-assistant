# 8-2179: Illegal Reference to Chandle
# 8-2179: Chandle에 대한 불법적인 언급

**Message:** `[Synth 8-2179] illegal reference to chandle type`
**메시지:** `[Synth 8-2179] Chandle 유형에 대한 잘못된 참조`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A `chandle` type is used in a non-DPI context or in a way that's not supported.
'chandle' 유형이 DPI가 아닌 컨텍스트에서 사용되거나 지원되지 않는 방식으로 사용됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: chandle used in synthesizable code
### P1: 합성 가능한 코드에 사용되는 챈들

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: chandle in synthesis context
chandle h;
assign out = h;  // ERROR: chandle not synthesizable
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: remove chandle
int handle_id;  // use integer as handle index
```

---

## Fix Strategy
## 전략 수정

1. Remove `chandle` from synthesizable RTL — it exists only to hold C pointers across the DPI boundary and has no hardware meaning.
1. 합성 가능한 RTL에서 `chandle`을 제거합니다. 이는 DPI 경계를 넘어 C 포인터를 보유하기 위해서만 존재하며 하드웨어 의미는 없습니다.
2. If you were using it as an identifier/handle, replace it with an integer index (`int`/`logic [N-1:0]`).
2. 식별자/핸들로 사용했다면 정수 인덱스(`int`/`logic [N-1:0]`)로 바꾸세요.
3. Keep any genuine DPI/`chandle` usage confined to testbench/verification code, guarded from synthesis.
3. 실제 DPI/`chandle` 사용을 테스트벤치/검증 코드로 제한하여 합성으로부터 보호하세요.
4. Redesign the data path so no opaque C handle is needed in hardware.
4. 하드웨어에 불투명한 C 핸들이 필요하지 않도록 데이터 경로를 재설계합니다.
