# 8-1859: Constant Not Allowed Here
# 8-1859: 여기서는 상수가 허용되지 않습니다.

**Message:** `[Synth 8-1859] constant is not allowed here`
**메시지:** `[Synth 8-1859] 상수는 여기서 허용되지 않습니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A constant expression is used in a context where a variable or signal is required.
상수 표현식은 변수나 신호가 필요한 상황에서 사용됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Attempt to modify a constant
### P1: 상수를 수정하려고 시도했습니다.

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: constant in wrong context
const int c = 5;
always_comb c++;  // ERROR: can't modify constant
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: use variable
int v = 5;
always_comb v = v + 1;  // mutable variable
```

---

## Fix Strategy
## 전략 수정

1. Declare the object as a mutable variable (`int`, `logic`, `reg`, or VHDL `variable`/`signal`) when it must be assigned/incremented — a `const`/`localparam`/`constant` cannot be modified.
1. 개체를 할당/증가해야 하는 경우 개체를 변경 가능한 변수(`int`, `logic`, `reg` 또는 VHDL `variable`/`signal`)로 선언합니다. `const`/`localparam`/`constant`는 수정할 수 없습니다.
2. If the value should never change, keep it constant and remove the code that tries to modify it (that code is the actual bug).
2. 값이 절대 변경되어서는 안 되는 경우에는 값을 일정하게 유지하고 값을 수정하려는 코드를 제거하세요(해당 코드가 실제 버그임).
3. Separate compile-time configuration (constants/parameters) from runtime state (variables/registers); do not reuse a constant as mutable storage.
3. 런타임 상태(변수/레지스터)와 컴파일 타임 구성(상수/매개변수)을 분리합니다. 상수를 변경 가능한 저장소로 재사용하지 마세요.
4. For accumulation, drive a register in a clocked block or a variable in a procedural block, seeded from the constant if needed.
4. 축적을 위해 클럭 블록의 레지스터나 필요한 경우 상수에서 시드된 절차 블록의 변수를 구동합니다.
