# 8-13159: RAM Dissolved into Registers
# 8-13159: 레지스터에 용해된 RAM

**Message:** `[Synth 8-13159] Potential Runtime issue for RAM since this is dissolved into registers`
**메시지:** `[Synth 8-13159] RAM이 레지스터에 용해되므로 RAM에 대한 잠재적인 런타임 문제`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

RAM is too large or coded improperly, causing Vivado to dissolve it into individual registers.
RAM이 너무 크거나 부적절하게 코딩되어 Vivado가 이를 개별 레지스터로 분해하게 됩니다.

---

## Common Patterns
## 일반적인 패턴

### P1: RAM dissolved into registers
### P1: RAM이 레지스터로 용해됨

**Problematic Code:**
**문제가 있는 코드:**
```diff
// RAM_reg dissolved into 32768 registers — very slow
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
-- Reduce RAM size or fix coding to enable BRAM inference
-- Check UG901 RAM templates
attribute ram_style of mem : signal is "block";
```

---

## Fix Strategy
## 전략 수정

1. Restructure the memory to a UG901 BRAM template (array indexed by address, synchronous registered read) so it infers Block RAM instead of dissolving into flip-flops.
1. 메모리를 UG901 BRAM 템플릿(주소로 색인화된 배열, 동기식 등록 읽기)으로 재구성하여 플립플롭으로 분해되는 대신 블록 RAM을 추론합니다.
2. Avoid asynchronous reads and unusual access patterns that prevent BRAM inference.
2. BRAM 추론을 방해하는 비동기 읽기 및 비정상적인 액세스 패턴을 피하세요.
3. Apply `ram_style = "block"` to steer inference for a legitimately large memory.
3. 합법적으로 큰 메모리에 대한 추론을 조정하려면 `ram_style = "block"`을 적용하세요.
4. Very large register-based RAMs cause timing/area issues — confirm BRAM mapping in the report.
4. 매우 큰 레지스터 기반 RAM으로 인해 타이밍/영역 문제가 발생합니다. 보고서에서 BRAM 매핑을 확인하세요.
