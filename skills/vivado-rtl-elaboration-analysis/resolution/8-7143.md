## Root Cause
## 근본 원인

A non-constant value is compared for equality against a static **metalogical**
상수가 아닌 값은 정적 **메타로지컬**과 동일한지 비교됩니다.
value (`'X'`, `'U'`, `'Z'`, `'-'`).
값(`'X'`, ``U'`, ``Z'`, ``-'`).
In synthesis such a comparison always
종합적으로 이러한 비교는 항상
evaluates to `false` (hardware signals are only 0/1), so the branch that depends
'false'(하드웨어 신호는 0/1에 불과함)로 평가되므로 의존하는 분기는
on it behaves differently than in simulation.
시뮬레이션과 다르게 동작합니다.

## Common Patterns
## 일반적인 패턴

### P1: Equality against a metalogical value
### P1: 금속학적 가치에 대한 동등성

**Problematic Code:**
**문제가 있는 코드:**
```diff
-- Problematic line:
process(in1, in2, in3, in4)
    begin
        out1 <= maximum(in1, in2);
        out2 <= func(in1, in3) xor func(in2, in4);
    end process;
```

**Recommended Fix:**
**권장 수정 사항:**
```vhdl
-- Do not compare signals against metalogical values in synthesizable RTL.
-- Use std_match for don't-cares, or compare only 0/1 values:
if in1 = '1' then ...            -- compare against 0/1 only
-- (move any 'X'/'U' checks into simulation-only assertions)
```

---

## Fix Strategy
## 전략 수정

1. Do not compare a signal against a metalogical literal (`'X'`, `'U'`, `'Z'`, `'-'`) in synthesizable RTL — in hardware such comparisons are always false.
1. 합성 가능한 RTL의 메타논리적 리터럴(`'X'`, `'U'`, `'Z'`, `'-'`)과 신호를 비교하지 마십시오. 하드웨어에서는 이러한 비교가 항상 거짓입니다.
2. Compare only against `'0'`/`'1'` (or use `std_match` for genuine don't-care patterns).
2. `'0'`/`'1'`에 대해서만 비교하십시오(또는 진정한 관심 패턴에는 `std_match`를 사용하십시오).
3. Move any `X`/`U` detection into simulation-only assertions, not into synthesized logic.
3. 'X'/'U' 감지를 합성 논리가 아닌 시뮬레이션 전용 어설션으로 이동합니다.
4. Verify the branch that depended on the metalogical compare still behaves correctly with 0/1-only logic.
4. 메타논리적 비교에 의존하는 분기가 여전히 0/1 전용 논리로 올바르게 작동하는지 확인합니다.
