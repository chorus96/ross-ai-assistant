# 8-10314: Break in Fork-Join
# 8-10314: 포크-조인 중단

**Message:** `[Synth 8-10314] break statement is not allowed within fork-join`
**메시지:** `[Synth 8-10314] break 문은 포크 조인 내에서 허용되지 않습니다.`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-10314] break statement is not allowed within fork-join [/path/to/file:NN]
```

---

## Root Cause
## 근본 원인

A `break` or `continue` statement is used inside a `fork`/`join` block, which is not allowed.
`break` 또는 `continue` 문은 `fork`/`join` 블록 내에서 사용되며 이는 허용되지 않습니다.
Also, `fork`/`join` is not synthesizable.
또한 `fork`/`join`도 합성할 수 없습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: break inside fork/join
### P1: 포크 내부 중단/조인

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: break inside fork-join (not synthesizable)
fork
begin
  if (count == 10) break;    // ERROR
  else continue;
end
join
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: replace with synthesizable sequential logic
always @(posedge clk) begin
  if (count < 10)
    out1 <= count ^ {in1, in2};
end
```

---

## Fix Strategy
## 전략 수정

1. `fork`/`join` (and `break`/`continue` inside it) are not synthesizable — rewrite the logic as sequential `always` blocks / an FSM.
1. `fork`/`join`(그리고 그 안에 있는 `break`/`continue`)은 합성할 수 없습니다. 로직을 순차적인 `always` 블록/FSM으로 다시 작성하세요.
2. Replace loop early-exit intent with explicit state/condition logic in a clocked block.
2. 루프 조기 종료 의도를 클록 블록의 명시적 상태/조건 논리로 대체합니다.
3. Move any genuine parallel simulation constructs into the testbench, out of synthesizable RTL.
3. 합성 가능한 RTL에서 실제 병렬 시뮬레이션 구성을 테스트벤치로 이동합니다.
4. Verify the sequentialized behavior preserves the intended data flow.
4. 순차화된 동작이 의도한 데이터 흐름을 유지하는지 확인합니다.
