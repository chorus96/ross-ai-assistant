# 8-5730: RAM i_0/PROC_IN_INST/METADATA_MNGR_INST/i_3 got...
# 8-5730: RAM i_0/PROC_IN_INST/METADATA_MNGR_INST/i_3이 있습니다...

**Message:** `[Synth 8-5730] RAM i_0/PROC_IN_INST/METADATA_MNGR_INST/i_3 got removed due to cross hierarchy optimization.`
**메시지:** `[Synth 8-5730] RAM i_0/PROC_IN_INST/METADATA_MNGR_INST/i_3이 계층 간 최적화로 인해 제거되었습니다.`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

An inferred RAM was removed during cross-hierarchy (boundary) optimization because
추론된 RAM은 계층 간(경계) 최적화 중에 제거되었습니다.
its outputs are ultimately unused, or its function collapsed to constants/pass-
그 출력은 궁극적으로 사용되지 않거나 그 기능이 상수/패스로 축소되었습니다.
through after optimization across module boundaries.
모듈 경계를 넘어 최적화 이후를 통해.
Vivado eliminated it since it
Vivado는 그 이후로 그것을 제거했습니다.
no longer contributes to any observable output.
더 이상 관찰 가능한 출력에 기여하지 않습니다.

## Common Patterns
## 일반적인 패턴

### P1: RAM whose outputs are not observable
### P1: 출력을 관찰할 수 없는 RAM

**Problematic Code:**
**문제가 있는 코드:**
```systemverilog
// metadata RAM written, but its read data never reaches a top-level output
always @(posedge clk) if (we) mem[addr] <= din;
assign dout = mem[raddr];   // 'dout' is left unconnected up the hierarchy
```

**Fix - ensure the RAM output propagates to a used output:**
**수정 - RAM 출력이 사용된 출력으로 전파되는지 확인하세요.**
```systemverilog
always @(posedge clk) begin
  if (we) mem[addr] <= din;
  dout <= mem[raddr];        // registered read, and 'dout' must be consumed
end
// ...and connect 'dout' through the hierarchy to a real sink
```

### P2: Intentional retention
### P2: 의도적인 보존

**Fix - if the RAM must be kept (e.g., for debug), mark it:**
**수정 - RAM을 유지해야 하는 경우(예: 디버그용) 다음과 같이 표시하세요.**
```systemverilog
(* dont_touch = "true" *) reg [7:0] mem [0:255];
```

## Fix Strategy
## 전략 수정

1. Trace the RAM's read data path to a top-level output — if nothing observes it, optimization legitimately removes it; connect the output to a real sink if it should be kept.
1. RAM의 읽기 데이터 경로를 최상위 출력까지 추적합니다. 아무것도 관찰되지 않으면 최적화가 합법적으로 이를 제거합니다. 유지해야 하는 경우 출력을 실제 싱크에 연결합니다.
2. Check for unconnected instance outputs across the hierarchy that make the whole RAM dead; wire them through.
2. 전체 RAM을 정지시키는 계층 전체의 연결되지 않은 인스턴스 출력을 확인하십시오. 연결해 보세요.
3. If the RAM is intentionally present (debug/probing), apply `(* dont_touch = "true" *)` / `keep_hierarchy` so it survives optimization.
3. RAM이 의도적으로 존재하는 경우(디버그/프로빙) `(* dont_touch = "true" *)` / `keep_hierarchy`를 적용하여 최적화 후에도 유지됩니다.
4. Confirm this removal is expected — if the RAM was supposed to be functional, the real bug is the missing downstream connection, not the optimization.
4. 제거가 예상되는지 확인하세요. RAM이 작동해야 한다면 실제 버그는 최적화가 아니라 다운스트림 연결이 누락된 것입니다.
