# 8-403: Loop Limit Exceeded
# 8-403: 루프 한계 초과

**Message:** `[Synth 8-403] loop limit (!%1!) exceeded`
**메시지:** `[Synth 8-403] 루프 제한(!%1!)이 초과되었습니다`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

A Verilog loop exceeds the synthesis tool's iteration limit (65536).
Verilog 루프가 합성 도구의 반복 제한(65536)을 초과했습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Procedural loop exceeds unroll limit
### P1: 절차적 루프가 언롤링 제한을 초과합니다.

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: loop runs too many iterations
for (i = 0; i < 100000; i = i + 1)  // ERROR: > 65536
  mem[i] = 0;
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: reduce iterations or restructure
genvar i;
generate
  for (i = 0; i < 256; i = i + 1)
    assign mem[i] = 0;
endgenerate
```

---

## Fix Strategy
## 전략 수정

1. Reduce the loop's iteration count below the synthesis unroll limit (65536); a loop bound that large is almost always a design mistake.
1. 루프의 반복 횟수를 합성 언롤 제한(65536) 아래로 줄입니다. 그렇게 큰 루프 경계는 거의 항상 설계 실수입니다.
2. Use a `generate` / `for-generate` construct for structural hardware replication instead of a procedural loop that must fully unroll.
2. 완전히 펼쳐야 하는 절차적 루프 대신 구조적 하드웨어 복제를 위해 '생성' / '생성용' 구문을 사용하세요.
3. Verify the loop bounds are correct elaboration-time constants — an accidental huge or wrong constant is the usual root cause.
3. 루프 경계가 올바른 정교화 시간 상수인지 확인하십시오. 실수로 거대하거나 잘못된 상수가 일반적인 근본 원인입니다.
4. Refactor the algorithm (e.g., process one element per clock in an FSM) so it does not require unrolling thousands of iterations into combinational hardware.
4. 수천 번의 반복을 조합 하드웨어로 전개할 필요가 없도록 알고리즘을 리팩터링(예: FSM에서 클록당 하나의 요소 처리)합니다.
