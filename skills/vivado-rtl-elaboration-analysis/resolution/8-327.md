# 8-327: Latch Inference
# 8-327: 래치 추론

**Message:** `[Synth 8-327] inferring latch for variable`
**메시지:** `[Synth 8-327] 변수에 대한 래치 추론`
**Severity:** WARNING
**심각도:** 경고
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Root Cause
## 근본 원인

Vivado infers a latch because a signal/variable is not assigned in all branches of combinational logic.
Vivado는 신호/변수가 조합 논리의 모든 분기에 할당되지 않기 때문에 래치를 추론합니다.

---

## Common Patterns
## 일반적인 패턴

### P1: Incomplete combinational assignment
### P1: 불완전한 조합 할당

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: missing else branch
always @(*)
  if (en) q = d;  // WARNING: latch on q
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: assign in all branches
always @(*)
  if (en) q = d;
  else q = 1'b0;
```

---

## Fix Strategy
## 전략 수정

1. Drive the variable in **every** path: add the missing `else`, or set a default value at the top of the combinational block before any conditionals.
1. **모든** 경로에서 변수를 구동합니다. 누락된 `else`를 추가하거나 조건 앞에 조합 블록 상단에 기본값을 설정합니다.
2. Make `case` statements full or add a `default`; a partial case infers a latch just like a missing `else`.
2. `case` 문을 가득 채우거나 `default`를 추가하세요. 부분적인 경우는 'else'가 누락된 것처럼 래치를 추론합니다.
3. Use `always_comb` (SystemVerilog) so incomplete assignments are flagged during elaboration.
3. `always_comb`(SystemVerilog)를 사용하면 완료되지 않은 할당이 상세화 중에 표시됩니다.
4. If the latch is intended (rare), document it deliberately; otherwise treat the warning as a functional bug and assign the signal on all branches.
4. 걸쇠를 의도한 경우(드물게) 의도적으로 문서화하십시오. 그렇지 않으면 경고를 기능적 버그로 처리하고 모든 분기에 신호를 할당합니다.
