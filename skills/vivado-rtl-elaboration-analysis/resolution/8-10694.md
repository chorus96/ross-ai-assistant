# 8-10694: Type Mismatch: chandle
# 8-10694: 유형 불일치: chandle

**Message:** `[Synth 8-10694] expected type chandle; observed type bit`
**메시지:** `[Synth 8-10694] 예상 유형 chandle; 관찰된 유형 비트`
**Severity:** ERROR
**심각도:** 오류
**Source:** Oasys Synthesis
**출처:** 오아시스 합성

---

## Vivado Message
## 비바도 메시지

```
ERROR: [Synth 8-10694] expected type chandle; observed type bit [/path/to/file:NN]
```

---

## Root Cause
## 근본 원인

`chandle` is a simulation-only type for C/DPI handles.
`chandle`은 C/DPI 핸들을 위한 시뮬레이션 전용 유형입니다.
Cannot be assigned from regular RTL types.
일반 RTL 유형에서는 할당할 수 없습니다.

---

## Common Patterns
## 일반적인 패턴

### P1: chandle in synthesizable code
### P1: 합성 가능한 코드의 챈들

**Problematic Code:**
**문제가 있는 코드:**
```diff
// Before: bit assigned to chandle
chandle ch1;
ch1 = in1;    // ERROR: can't assign bit to chandle
```

**Recommended Fix:**
**권장 수정 사항:**
```diff
// After: remove chandle (not synthesizable)
// chandle is for DPI-C interfaces only — not synthesizable
// Replace with integer or pointer-like index:
int ch_index;
ch_index = int'(in1);
```

---

## Fix Strategy
## 전략 수정

1. `chandle` is for the C/DPI boundary and is not synthesizable — remove it from synthesizable RTL.
1. `chandle`은 C/DPI 경계용이므로 합성할 수 없습니다. 합성 가능한 RTL에서 제거하세요.
2. Replace an opaque handle with an integer index (`int`/`logic [N-1:0]`) if you need an identifier.
2. 식별자가 필요한 경우 불투명 핸들을 정수 인덱스(`int`/`logic [N-1:0]`)로 바꾸세요.
3. Keep genuine DPI/`chandle` usage confined to verification code.
3. 정품 DPI/`chandle` 사용을 인증 코드에만 국한하여 유지하세요.
4. Redesign the data path so no C pointer is needed in hardware.
4. 하드웨어에 C 포인터가 필요하지 않도록 데이터 경로를 다시 설계하십시오.
