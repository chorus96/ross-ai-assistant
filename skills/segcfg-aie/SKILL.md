Explain how AI Engines interact with Segmented Configuration and guide the user through the combined AIE + segmented config design and build flow.
AI 엔진이 세그먼트 구성과 상호 작용하는 방식을 설명하고 결합된 AIE + 세그먼트 구성 설계 및 빌드 흐름을 통해 사용자를 안내합니다.

## Instructions
## 지침

1. Explain **AI Engine configuration partitioning** in a Segmented Configuration design:
1. 세그먼트화된 구성 설계에서 **AI 엔진 구성 분할**을 설명하세요.
   - The AIE configuration path and config tile (PLL, clocking) go into **boot.pdi**
   - AIE 구성 경로 및 구성 타일(PLL, 클로킹)은 **boot.pdi**로 이동합니다.
   - The AIE array configuration and core ELFs are packaged with pl.pdi into **pl_aie.pdi**
   - AIE 어레이 구성 및 핵심 ELF는 pl.pdi와 함께 **pl_aie.pdi**에 패키지되어 있습니다.
   - An AIE-only PDI can be separately packaged and loaded after pl.pdi if needed
   - AIE 전용 PDI는 필요한 경우 pl.pdi 이후에 별도로 패키징하고 로드할 수 있습니다.

2. Explain **XSA export** considerations:
2. **XSA 내보내기** 고려 사항을 설명하세요.
   - The design must include the AI Engine and its NoC configuration path
   - 설계에는 AI 엔진과 해당 NoC 구성 경로가 포함되어야 합니다.
   - `write_hw_platform` automatically generates a Segmented Configuration extensible XSA
   - `write_hw_platform`은 세그먼트 구성 확장 가능한 XSA를 자동으로 생성합니다.
   - No additional flags needed — the segmented nature is detected from the project property
   - 추가 플래그가 필요하지 않습니다. 분할된 특성이 프로젝트 속성에서 감지됩니다.

3. Explain the **Vitis v++ Hardware Flow**:
3. **Vitis v++ 하드웨어 흐름**을 설명하세요.
   - `boot.pdi`: build and configuration steps are identical to the standard (non-segmented) Vivado flow
   - `boot.pdi`: 빌드 및 구성 단계는 표준(분할되지 않은) Vivado 흐름과 동일합니다.
   - `pl_aie.pdi`: build and load process is the same as the standard Vitis flow
   - `pl_aie.pdi`: 빌드 및 로드 프로세스는 표준 Vitis 흐름과 동일합니다.
   - `xclbin`: Vitis metadata generated by the `v++` packager; host application reads it identically to a non-segmented design
   - `xclbin`: `v++` 패키지 프로그램에 의해 생성된 Vitis 메타데이터; 호스트 애플리케이션은 분할되지 않은 설계와 동일하게 읽습니다.
   - No special v++ flags are needed to support Segmented Configuration
   - 세그먼트 구성을 지원하는 데 특별한 v++ 플래그가 필요하지 않습니다.

4. Explain the **Vitis v++ Hardware Emulation (HW_EMU) Flow**:
4. **Vitis v++ 하드웨어 에뮬레이션(HW_EMU) 흐름**을 설명하세요.
   - HW_EMU focuses on simulating application execution, not PDI configuration behavior
   - HW_EMU는 PDI 구성 동작이 아닌 애플리케이션 실행 시뮬레이션에 중점을 둡니다.
   - Compatible with Segmented Configuration-enabled designs without modification
   - 수정 없이 분할 구성 지원 설계와 호환 가능
   - Pre-loads PL contents using RTL simulators (no runtime PDI loading in emulation)
   - RTL 시뮬레이터를 사용하여 PL 콘텐츠를 사전 로드합니다(에뮬레이션에서 런타임 PDI 로드 없음).
   - Dynamically loads AIE configuration using `fpgautil aie_pl.pdi`, but ignores PL configuration data (already pre-loaded by simulator)
   - `fpgautil aie_pl.pdi`를 사용하여 AIE 구성을 동적으로 로드하지만 PL 구성 데이터는 무시합니다(이미 시뮬레이터에 의해 사전 로드됨).
   - Host application reads xclbin metadata the same way as in the hardware flow
   - 호스트 응용 프로그램은 하드웨어 흐름과 동일한 방식으로 xclbin 메타데이터를 읽습니다.

5. Provide **design guidance** for AIE + Segmented Configuration:
5. AIE + 세그먼트 구성에 대한 **설계 지침** 제공:
   - Ensure the NoC path connecting PS to the AIE configuration tile has `initial_boot = true` set
   - PS를 AIE 구성 타일에 연결하는 NoC 경로에 'initial_boot = true'가 설정되어 있는지 확인하세요.
   - This ensures the AIE config tile is initialized in boot.pdi so the array is ready when pld.pdi loads the ELFs
   - 이렇게 하면 AIE 구성 타일이 boot.pdi에서 초기화되어 pld.pdi가 ELF를 로드할 때 어레이가 준비됩니다.
   - Verify and set the NoC `initial_boot` paths in Vivado before implementation
   - 구현 전에 Vivado에서 NoC 'initial_boot' 경로를 확인하고 설정하세요.
   - Validate with `/segcfg-design-check` — run SEGCONFIG DRCs to confirm AIE NoC paths are correct
   - `/segcfg-design-check`로 유효성을 검사합니다. SEGCONFIG DRC를 실행하여 AIE NoC 경로가 올바른지 확인합니다.

6. For **AIE + PL Reload** scenarios:
6. **AIE + PL 다시 로드** 시나리오의 경우:
   - The AIE configuration tile (in boot.pdi) remains constant across PL reload operations
   - AIE 구성 타일(boot.pdi)은 PL 다시 로드 작업 전반에 걸쳐 일정하게 유지됩니다.
   - AIE array configuration and ELFs (in pl_aie.pdi) can change with each PL variant
   - AIE 어레이 구성 및 ELF(pl_aie.pdi)는 각 PL 변형에 따라 변경될 수 있습니다.
   - The golden design must establish the full AIE NoC path superset (same rule as PL boundary)
   - 골든 디자인은 전체 AIE NoC 경로 상위 집합을 설정해야 합니다(PL 경계와 동일한 규칙).
   - Import the NoC solution file from the golden run before compiling AIE variants
   - AIE 변형을 컴파일하기 전에 골든 런에서 NoC 솔루션 파일을 가져옵니다.

7. Reference documentation:
7. 참조 문서:
   - UG1701: Vitis AI Engine documentation covering Segmented Configuration + AIE emulation flow details
   - UG1701: 세그먼트 구성 + AIE 에뮬레이션 흐름 세부 정보를 다루는 Vitis AI 엔진 문서
   - Use Vivado `write_device_image` to produce boot.pdi and pl_aie.pdi
   - Vivado `write_device_image`를 사용하여 boot.pdi 및 pl_aie.pdi 생성

8. Ask the user which part of the flow they need help with:
8. 사용자에게 흐름 중 어떤 부분에 도움이 필요한지 물어보세요.
   - Setting up the design with AIE included
   - AIE가 포함된 디자인 설정
   - Exporting XSA for Vitis
   - Vitis용 XSA 내보내기
   - Building with v++ for hardware or emulation
   - 하드웨어 또는 에뮬레이션을 위해 v++로 빌드
   - Running PL reload with AIE variants
   - AIE 변형으로 PL 다시 로드 실행
